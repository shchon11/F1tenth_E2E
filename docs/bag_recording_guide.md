# 실차 rosbag 녹화 안내서 (2026-11-28)

대상 차: RoboRacer(F1TENTH) 계열, VESC, 2D LiDAR, IMU, Jetson, ROS 2 Humble.
목적: 레이스 주행을 아무렇게나 녹화해서는 알 수 없는 값을 얻으려면 **어떤 주행을, 어떤 토픽으로, 얼마나** 녹화해야 하는지를 현장에서 그대로 따라 할 수 있게 적는다.

이 문서의 숫자에는 세 가지 출처가 있다. 읽을 때 구분할 것.

- **(도구 문턱값)**: `f1sim/f1sim/bag_profile/thresholds.py` 한 곳에 이름 붙은 상수로 모여 있는 값이고, 도구가 낸 `summary.md` 맨 끝에 그 실행에 쓴 값 표가 붙는다. 이 이하로 찍으면 도구가 "측정됨"을 내지 않는다. 문서와 코드가 어긋나면 그 표가 맞다.
- **(권장)**: 문턱값이 아니라, 문턱값을 안전하게 넘기려고 이 문서가 정한 값.
- **(미검증)**: 이 PC에서 실차로 확인하지 못한 것. 현장에서 먼저 확인할 것.

용어: **트림**은 직진 보정(조향을 0으로 줘도 차가 한쪽으로 휘는 만큼의 조향 오프셋), **서보 창**은 VESC가 서보에 허용하는 위치 범위(이 밖의 명령은 잘림), **ERPM 환산**은 속도 [m/s]를 모터 회전수 [ERPM]로 바꾸는 비, **그립 하한**은 "차가 이만큼의 횡가속을 잃지 않고 버텼다"는 값(실제 최대 마찰은 이보다 크거나 같다).

## 2. 녹화 전 준비

### 2.1 토픽 표

bag_profile은 토픽을 **이름과 메시지 형식**으로 찾는다. 이름이 다르면(예: `/ackermann_cmd`가 아닌 다른 이름) 같은 형식의 다른 토픽을 쓰기도 하지만, 엉뚱한 토픽을 고를 수 있으니 이름을 그대로 쓰는 편이 안전하다.

필수 (하나라도 없으면 아래 "빠지면" 열의 손실):

| 토픽 | 메시지 형식 | 쓰이는 값 | 빠지면 |
|---|---|---|---|
| `/sensors/imu/raw` | sensor_msgs/Imu | 요레이트, 횡·종가속, 바이어스, 단위 판정, 지연, 트림, 그립 하한, 타이어 값 | **도구가 중단된다**(오류 종료). 동역학 값 전부 불가 |
| `/ackermann_cmd` | ackermann_msgs/AckermannDriveStamped | **서보 변환식**(서보 명령과 짝지어 맞춤), 속도 지령 | 변환식을 못 맞춤(프로필 값 대체). 주의: 이 토픽이 없으면 `/drive`, `/teleop`을 대신 쓰는데 시간이 달라 짝이 안 맞을 수 있음 |
| `/commands/servo/position` | std_msgs/Float64 | 서보 변환식, 서보 창(잘리기 전 명령), 명령 끊김 검사(재생 구간은 이 토픽이 0.1 s 넘게 안 나오면 버림) | 변환식·창 불가, 조향은 Ackermann 값에서 |
| `/sensors/servo_position_command` | std_msgs/Float64 | **VESC가 실제로 적용한 서보 위치** → 서보 창, 적용된 조향 | 창을 못 봄. 재생이 잘리기 전 명령을 써서 창 근처에서 틀림 |
| `/commands/motor/speed` | std_msgs/Float64 | ERPM 환산, 속도 지령 | `/odom`으로 대체 |
| `/sensors/core` | vesc_msgs/VescStateStamped | 바퀴 속도(회전수), **모터 전류**, 듀티, 전압 | 가속·제동 한계, 전류 한계 불가. 속도는 `/odom`에서 |
| `/odom` | nav_msgs/Odometry | 환산 교차 검사, 회전수 양자 | 교차 검사 불가 |
| `/scan` | sensor_msgs/LaserScan | LiDAR 잡음·누락·유효 빔, 지도 | LiDAR 값, 지도 불가 |
| `/tf_static` | tf2_msgs/TFMessage | LiDAR 장착 위치(프레임 이름이 `laser`, `lidar`, `laser_frame` 중 하나여야 함) | 장착 위치 모름 |

권장:

| 토픽 | 쓰이는 값 | 빠지면 |
|---|---|---|
| `/pf/pose/odom` (또는 `/car_state/odom`, `/pf/viz/inferred_pose`) | 자이로 단위 판정의 독립 기준, 위치 오차, 지도 축척 검사 | 자이로 단위는 조향 운동학으로만 판정. 축척 검사 불가 |
| `/map` | 장소 코드(지도 크기·해시), 지도 | 지도 없음(스캔으로 만들려면 ROS 환경 필요) |
| `/sysid/segment` (std_msgs/String) | 구간 표시(`T3 start` / `T3 end`). **있으면 시험별 계산(T1 서보 창 끝, T2 저속 선회, T3 가속·제동·전류 한계, T4 코스트다운, T5 조향 응답, T6 그립)을 그 구간 안으로 자른다.** 요약에 어느 방식이 쓰였는지 값마다 적힘 | 도구가 규칙으로 구간을 찾는다(자동 인식, 4장). 시험이 섞인 bag에서는 틀린 구간을 고를 수 있다 |
| `/tf`, `/drive`, `/teleop`, `/joy` | 도구는 안 읽음. 사후 확인용(누가 운전했나) | 없음 |

형식 관련 주의 세 가지.

1. **저장 형식은 sqlite3(Humble 기본)만 읽는다.** mcap(`-s mcap`)로 저장하면 읽지 못하고, 도구는 "mcap 이라 못 읽음"과 변환 방법(`ros2 bag convert -i <bag> -o convert.yaml`, convert.yaml 에 `storage_id: sqlite3`)을 오류 메시지로 알려 주고 종료 코드 2로 끝난다. 메시지 직렬화는 CDR 리틀엔디언만.
2. **쪼개진 bag(`.db3`가 여러 개)도 전부 읽는다**(`--max-bag-size` 등). 요약 맨 위에 읽은 파일 수가 적힌다. 그래도 bag 하나 = 시험 하나 원칙이 편하므로 쪼개기 옵션은 쓰지 않는 편이 낫다.
3. `/sensors/core`는 필드 순서가 고정이라는 가정으로 읽는다(온도 2개, 전류 2개, d·q 전류 2개, 듀티, 속도, 전압). 차의 `vesc_msgs` 버전이 다르면 값이 조용히 틀릴 수 있다 → 현장 확인 때 전류 최대·최소가 설정과 맞는지 본다(5장).

### 2.2 녹화 명령 (복사해서 사용)

(미검증: 이 PC에서 실차로 실행하지 않았다. 토픽 이름은 기존 실차 bag의 `metadata.yaml`에서 확인한 것이다.)

```bash
# bag 하나 = 시험 하나. 폴더 이름 규칙은 2.4.  분할 옵션 없음, 저장 형식 sqlite3(기본).
ros2 bag record -o 20261201-101500_T3-launch-brake \
  /ackermann_cmd /commands/servo/position /sensors/servo_position_command \
  /commands/motor/speed /sensors/core /sensors/imu/raw /odom /scan \
  /tf_static /pf/pose/odom /map /sysid/segment /drive /teleop /joy
```

`/map`과 `/tf_static`은 한 번만 발행되는 토픽이다. 대회 때 bag에는 각 1개씩 들어 있었다. 기록기가 시작된 뒤 지도 서버가 뜨도록 순서를 지키지 말고, 시험 전에 `ros2 topic echo --once /tf_static`으로 나오는지 먼저 본다.

**정지 구간은 명령이 안 나가도 쓰인다.** 도구의 100 Hz 격자는 IMU와 `/sensors/core`가 있는 구간 전체에 걸쳐 만들어지므로, 명령 토픽이 없는 정지 구간에서도 IMU 바이어스와 LiDAR 정지 잡음을 계산한다. 다만 명령이 없는 구간은 응답·지연·트림·재생 구간 계산에는 쓰이지 않는다(그 계산은 명령이 있어야 한다). 정지 중 속도 0 지령을 계속 내 두면 더 안전하지만(자율 주행 노드를 켜 둔 채 정지) 필수는 아니다.

### 2.3 차 설정 기록 `setup.yaml` (bag 폴더 안이나 그 옆에, 손으로)

**도구가 이 파일을 읽는다.** 위치는 `--setup <경로>`로 준 파일, 없으면 bag 폴더 안의 `setup.yaml`, 그것도 없으면 bag 폴더 바로 옆(부모 폴더)의 `setup.yaml`. 하는 일은 둘이다.

1. **대조**: `vesc`·`imu`·`lidar` 칸의 설정값을 bag에서 역추정한 값과 항목마다 맞춰 보고 `summary.md`에 "일치 / 불일치(차이) / 비교 불가(이유)"로 적는다. 서보 이득·오프셋, ERPM 환산, 서보 창 양 끝, 구동·회생 전류 한계, 자이로·가속도 단위, LiDAR 프레임 이름과 tf. 허용 차는 `thresholds.py`의 `SETUP_TOL_*`. 이 파일 하나가 서보 부호 반전, 자이로 단위, 회생 전류 차이 같은 과거 사고를 막는다.
   - 서보 창 끝이나 전류 한계가 bag에서 "하한만"이면 "설정값이 bag의 값보다 작지 않다"만 확인하고 "일치(하한만 확인)"으로 적는다.
2. **수동 실측 입력**: `hand_measured:` 칸(아래)의 값은 출력 `car_calibration.yaml`에 출처 `실측(수동)`(`origin: manual`)으로 들어간다. 질량·무게중심·요 관성은 `vehicle.m`, `vehicle.lr`·`lf`, `vehicle.Iz`로 들어가 `f1sim.profiles.loader`가 시뮬 설정에 얹을 수 있다. LiDAR 실측은 `lidar.mount_x`·`mount_z`를 바꾼다. 바퀴 각 표는 `car.wheel_angle_table`과 이를 원점을 지나는 직선으로 맞춘 `car.steer_gain_wheel`(바퀴 각 / 명령 조향각)이 된다. 입력한 항목은 요약의 "못 잰 것 (b)" 목록에서 빠진다.

읽지 못한 키(오타)는 요약에 "읽지 않은 키"로 나열된다.

```yaml
date: 2026-12-01
place: 대회장 A 트랙            # 장소 이름. 노면이 다르면 같이 맞추면 안 된다
surface: 매트 / 콘크리트 / ...   # 재질
vesc:
  speed_to_erpm_gain: 4204      # 대회 차 값. bag에서 도구가 다시 구해 대조
  servo_min: 0.235              # VESC 설정의 서보 범위 (서보 값, 0~1)
  servo_max: 0.655
  steering_to_servo_gain: 0.630 # 서보 = gain * 조향[rad] + offset
  steering_to_servo_offset: 0.395
  current_motor_max_A: 60       # 설정한 구동 전류 한계
  current_regen_min_A: -30      # 설정한 회생 전류 (대회 차 -30, 사전 차 -5였다)
imu:
  driver: <패키지·버전>
  gyro_unit: rad/s              # 7월 bag 7개는 deg/s였다
  accel_unit: g                 # 선가속도는 g 단위로 나온다
lidar:
  tf_base_to_laser: [0.297, 0.0, 0.110]   # 설정값. 실측은 정밀 세트 A7
  frame_name: laser
tyre: <모델 / 신품·사용 / 공기압>
battery_v_start: 16.4
battery_v_end: 15.9             # 구동 한계가 전압에 따라 내려간다
changed_since_last: >
  타이어·서보 혼·링키지·VESC 설정·배터리 등 바뀐 것은 모두. 바뀌었으면 그 시험부터 버린다

# 주행 녹화로는 안 나오는 값. 잰 것만 적는다(재지 않은 항목은 지우거나 비워 둔다)
hand_measured:
  wheel_angle_table:            # 정지 상태. 명령 조향각 [rad] -> 실제 바퀴 각 [deg] (왼쪽 양수, 좌우 평균을 씀)
    - {cmd_rad: 0.15, left_deg: 5.3, right_deg: 4.6}
    - {cmd_rad: 0.30, left_deg: 10.1, right_deg: 8.9}
  mass_kg: 3.9                  # 저울
  wheelbase_m: 0.3302           # 생략하면 0.3302
  cg_from_rear_axle_m: 0.17     # 뒤차축에서 무게중심까지 (바퀴별 저울로 계산)
  yaw_inertia_kgm2: 0.047       # 매달기·진자
  lidar_mount_m: [0.297, 0.0, 0.110]   # base_link(뒤차축) 기준 x, y, z, 줄자
```

(위 hand_measured 의 숫자는 양식을 보이는 자리표시이고 잰 값이 아니다. `docs/pm/sysid-2026-11-28/examples/setup_example_competition.yaml`은 대회 차의 설정 칸만 채운 예시다.)

### 2.4 폴더 이름 규칙

`<YYYYMMDD-HHMMSS>_<장소 약칭>_<시험 번호>-<내용>`. 예: `20261201-101500_siteA_T3-launch-brake`.

- 앞의 날짜·시각은 필수다. 도구는 폴더 이름 앞 15자를 그 bag의 이름으로 쓴다(`--name`으로 바꿀 수 있음).
- 장소는 도구가 `/map`의 크기와 해시로 자동 판정한다(`map08x23` = 8.4 × 22.6 m). 이름에 장소를 적는 건 사람용이다.
- 기존 `real_data/`의 이름 규칙(`..._v<최고속도>_<길이>s_<태그>`)은 녹화 후 정리할 때 쓴다.
- 시험 중에 설정을 바꾸면 이름에 `CHG-<무엇>`을 붙인다.

### 2.5 구간 표시

한 bag에 시험을 여러 개 넣어야 할 때(최소 세트)는 시험 시작과 끝에 표시를 낸다. 형식은 `<시험 이름> start` / `<시험 이름> end`(`T0`~`T7`, 대소문자 무시).

```bash
ros2 topic pub -t 3 -r 3 /sysid/segment std_msgs/msg/String "{data: 'T3 start'}"
ros2 topic pub -t 3 -r 3 /sysid/segment std_msgs/msg/String "{data: 'T3 end'}"
```

(미검증: Humble의 `--once`는 구독자를 기다리지 않을 수 있어 3번씩 내도록 했다. 같은 표시가 3개 보이는 건 정상.) 도구는 표시를 읽어 그 시험의 계산을 표시된 구간 안으로 자르고, 요약의 "계산에 쓴 구간" 표에 값마다 "표시 토픽(T3: 2개 구간, 14 s)" 또는 "자동 인식"으로 적는다. 표시에 그 시험이 없으면 그 값만 자동 인식으로 돌아간다. 같은 표시가 2 s 안에 되풀이되면(위처럼 3번 냈을 때) 한 번으로 센다. end 없이 끝난 start 는 bag 끝까지로 치고 경고한다. 지연·트림·재생 맞춤·IMU 바이어스·LiDAR 통계는 표시와 무관하게 bag 전체로 계산한다. 시험당 bag 하나로 나누면 표시는 필요 없다.

### 2.6 용량

기존 실차 bag 측정: 모든 토픽을 찍으면 초당 약 2.7 MB(161 s에 434 MB). 위 2.2의 토픽만 찍으면 대부분 `/scan`(초당 약 0.35 MB)이고, 합쳐 초당 약 0.5 MB 안팎으로 본다(권장 추정). 표준 세트 전체(약 25분 녹화)는 1 GB 안쪽. 여유 공간 5 GB 이상에서 시작한다. `/map`을 5 Hz로 다시 내보내는 환경(사전 bag이 그랬다, 21 s에 4.8 MB)이면 용량이 늘어난다.

### 2.7 매 bag 앞뒤에 정지 구간을 두는 이유

- 앞 정지: 바이어스 영점(주행 중 온도로 바이어스가 움직이므로 bag마다 필요), 가속도 단위 확인(정지 시 |a| ≈ 1이면 g, ≈ 9.8이면 m/s²), LiDAR 정지 잡음.
- 뒤 정지: 위 값의 재확인.
- 길이: 도구 최소 1 s. 첫 bag(T0)은 10 s 이상, 나머지는 5 s 이상(권장). 정지 중 차를 건드리거나 사람이 LiDAR 앞을 지나가면 안 된다.

## 4. 시험별 상세 절차 (표준 세트)

공통 사항.

- **명령 보내는 법.** 조이스틱은 정지 상태 풀락(T1)과 자유 주행에만 쓴다. 정해진 값(속도 7 m/s, 조향 0.25 rad를 일정 시간)은 사람 손으로 못 맞추므로 `ros2 topic pub`이 필요하다. 아래 예는 자율 주행 입력 `/drive`에 내는 방식이다. **(미검증)** 이 차의 명령 중재기가 `/drive`를 받아들이는 조건(조이스틱 확인 버튼 등)은 현장에서 먼저 확인한다. 기존 bag의 조이스틱 입력(`/teleop`)은 값이 전부 0이어서, 조이스틱 풀 스틱이 몇 rad로 나가는지는 기존 bag으로 확인하지 못했다.
- **명령은 40 Hz로 끊김 없이.** 재생 구간은 서보 명령 토픽이 0.1 s 넘게 비면 버려진다.
- **명령 예시**

  ```bash
  # 조향 0.25 rad, 속도 1.3 m/s 를 40 Hz로 계속. Ctrl-C 로 멈춤
  ros2 topic pub -r 40 /drive ackermann_msgs/msg/AckermannDriveStamped \
    "{drive: {steering_angle: 0.25, speed: 1.3}}"
  ```

  명령을 바꿀 때 `ros2 topic pub`을 껐다 켜면 약 1 s 공백이 생겨 중재기가 정지 명령을 낼 수 있다. 공백 없이 정해진 순서로 내는 발행기는 **저장소에 없다**(8장). 그 전까지는 공백이 생겨도 위험하지 않은 시험(정지 상태 T1, 속도 0이 안전한 T3 종료)에 쓰거나, 사람이 조이스틱 확인 버튼으로 즉시 끊을 수 있게 둔다.
- **안전 공통.** 시험 전에 조이스틱 확인 버튼을 놓으면 차가 서는지 먼저 확인한다. 시험장 둘레의 사람은 차에서 4 m 이상. 시험 도중 설정(타이어·배터리)을 바꾸지 않는다.
- **합격 확인.** 시험마다 찍자마자 5장의 방법으로 도구를 돌려 해당 줄이 "측정됨"이 되는지 본다.

### T0. 정지 10 s

- **목적**: 바이어스, 가속도 단위, LiDAR 정지 잡음, 서보 명령과 센서가 모두 나오는지 확인.
- **공간·준비물**: 평평한 바닥. 준비물 없음. 사람이 LiDAR 시야에서 떠나 있을 것.
- **주행 방법**: 없음. 속도 0 지령을 계속 내며(자율 주행 노드 대기 또는 `ros2 topic pub -r 40 /drive ... "{drive: {steering_angle: 0.0, speed: 0.0}}"`) 10 s 이상 정지.
- **길이·반복**: 10 s, 1회. 다른 시험 bag도 앞뒤에 5 s씩 이 정지를 둔다.
- **합격 조건 (도구)**: 요약의 `car.imu_bias`가 값을 가진다(바퀴 속도 < 0.02 m/s가 1 s 이상 이어진 구간. 명령 토픽 유무와 무관하게 bag 전체의 정지 구간을 쓴다). LiDAR 잡음이 나오려면 휠 속도 |v| < 0.01 m/s이고 자이로 크기 0.03 rad/s 미만인 1 s 블록이 필요하고, 블록 안에서 90 % 넘게 유효한 빔이 있어야 한다. 요약의 "정지 잡음" 행이 나오면 합격(대회 bag 값 약 4~5 mm).
- **흔한 실수**: 차를 건드림. 정지 직후 바로 시작해 휠 속도가 0.02 m/s 넘게 남음. (명령을 안 내도 정지 구간은 쓰인다, 2.2.)
- **안전**: 없음.

### T1. 정지 조향 계단 + 바퀴 각 실측

- **목적**: 서보 변환식과 서보 창 양 끝을 확정하고, 명령 조향각이 실제 바퀴 각과 얼마나 다른지 잰다.
- **공간·준비물**: 어디서나. 바퀴를 띄우면(받침 위) 각도 읽기가 쉽고 서보 부하가 적어 더 정확하다(접지 상태와 약간 다를 수 있음). 각도지 인쇄물(중심을 킹핀 축에 맞춤) 또는 바퀴 바로 위 삼각대 촬영.
- **주행 방법**: 속도 0으로 조향만. 조향 0 → +0.15 → +0.30 → +0.45 → 0 → −0.15 → −0.30 → −0.45 → 0, 각 3 s 유지. `/ackermann_cmd`에서 ±0.45 rad까지 나간 기록이 기존 bag에 있다. 이 값이 서보 창보다 커야 창 끝이 보인다(대회 차 창 −0.254/+0.412 rad). 조이스틱 풀 스틱이 ±0.45 rad인지는 (미검증), 모르면 `ros2 topic pub`으로 0.45를 직접 낸다. 유지 구간마다 좌·우 바퀴 각을 사진 1장으로 남긴다.
- **길이·반복**: 약 30 s, 왕복을 한 번 더(백래시 확인) 총 약 1분.
- **합격 조건 (도구)**
  - 서보 변환식: 짝지은 명령 20쌍 이상, 조향 표준편차 0.02 rad 이상이면 맞춤이 나온다. 요약에서 `servo_map_gain` 상태가 "측정됨"이고 방법 칸이 `fit:`으로 시작해야 한다("not identified"면 실패).
  - 서보 창: 양쪽 끝 각각 창 밖 명령이 3개 이상(풀락 3 s면 100개 넘게 나옴). 요약의 `steer_window` 메모가 "양쪽 끝 모두 잘림이 관측됨"이어야 한다.
  - 바퀴 각 실측은 주행 신호가 아니므로 손으로 잰다. `setup.yaml`의 `hand_measured.wheel_angle_table`에 명령 조향각과 좌·우 바퀴 각을 적으면 도구가 `car.steer_gain_wheel`(바퀴 각 / 명령 조향각)로 맞춰 출력한다(2.3). 서보 값과의 대응표는 `notes.md`에도 남긴다.
  - `/sysid/segment`에 `T1 start/end`가 있으면 서보 창 끝은 그 구간의 명령·적용 위치만으로 센다.
- **흔한 실수**: 풀락을 창보다 작게 줌(0.30만 줌) → 한쪽 끝 "하한만". 오른쪽과 왼쪽의 창이 다르다는 걸 모르고 한쪽만 확인. 서보가 움직이는 중에 사진을 찍음(3 s 기다릴 것).
- **안전**: 차가 움직이지 않도록 모터 전원 확인(속도 0). 바퀴를 띄운 경우 속도 지령은 반드시 0.

### T3. 직선 풀가속 → 급제동

- **목적**: 구동 가속 한계 a_max와 속도에 따른 감소(v_switch), 제동 한계 a_brake, 구동·회생 전류 한계.
- **공간·준비물**: 직선 15 m 이상(20 m 권장). 끝에 여유 3 m 이상. 배터리 완충. 배터리 전압을 시작·끝에 적는다(구동 한계가 전압에 딸림).
- **주행 방법**: 정지에서 속도 지령 7 m/s → 속도가 6 m/s를 넘으면 속도 지령 0(회생 제동). 거리 계산(권장 추정): 가속 약 4.5 m/s²이면 6.5 m/s까지 약 5 m, 제동 약 4.8 m/s²이면 약 4.4 m. 9 m/s 구간까지 얻으려면 20 m 이상 필요하다. 세 구간(0.3~3, 3~5, 5~7 m/s)에서 전류가 한계에 있어야 a_max가 "측정됨"이다.
  명령은 `timeout`으로 순서를 낸다(공백에 주의, 위 공통 사항).

  ```bash
  timeout 2.5 ros2 topic pub -r 40 /drive ackermann_msgs/msg/AckermannDriveStamped \
    "{drive: {steering_angle: 0.0, speed: 7.0}}" ; \
  timeout 3.0 ros2 topic pub -r 40 /drive ackermann_msgs/msg/AckermannDriveStamped \
    "{drive: {steering_angle: 0.0, speed: 0.0}}"
  ```

  (미검증: 2.5 s는 지금 설정으로 6 m/s에 닿는 시간이어야 하며 차에 맞춰 조정한다. 앞 `timeout`이 끝나고 다음 `ros2 topic pub`이 뜨기 전 공백이 있다. 그 사이 명령이 끊기면 중재기가 감속시키는 것은 이 시험에서는 괜찮다.)
- **길이·반복**: 한 번에 약 8 s, 3~4회(왕복하며 노면 경사 상쇄).
- **합격 조건 (도구)**
  - 구간: `T3 start/end` 표시가 있으면 그 구간 안만 쓴다(없으면 bag 전체에서 아래 규칙으로).
  - 구동: 전류가 그 bag의 **0.1 % 상위값(p99.9)의 90 % 이상**인 구간이 0.2 s 이상(양 끝 50 ms씩 깎임), v > 0.3 m/s. 속도 구간 5개 중 3개 이상에서 10샘플 이상이면 `a_max`와 `v_switch`가 "측정됨". 아니면 `a_max` "하한만".
  - 제동: 전류가 **0.1 % 하위값(p0.1)의 90 % 이하**(더 음수)인 구간이 0.2 s 이상이면 `a_brake`가 나온다. 구간 수 조건은 없다.
  - **전류 한계의 상태**: `car.current_max`·`car.current_min`은 전류가 한계에 **붙어 평평하게 유지된 구간**이 확인될 때만 "측정됨"이다. 기준(도구 문턱값): 극값(p99.9, 회생은 p0.1)의 2 % 안에 머무는 연속 구간이 0.2 s 이상이고, 그런 구간이 0.5 s 이상 떨어져 2개 이상. 값은 평평한 구간 샘플의 중앙값, 오차는 그 표준편차. 기준을 못 채우면 극값이 "하한만"으로 나오고(요약의 방법 칸에 평평한 구간이 몇 개였는지 적힘) "못 잰 것 (a)"에 올라간다. 완만한 가속은 평평한 구간이 되지 않는다. 설정값과의 대조는 `setup.yaml`이 한다.
- **흔한 실수**: 지령이 낮아서(5 m/s) 7 m/s 구간이 비어 구간 수 부족. 전류 한계에 안 걸린 가속(완만한 램프)을 한계로 착각(이제는 "하한만"으로 표시됨). 완충이 아니라서 낮은 전압에서 값이 나옴.
- **안전**: 끝에서 서지 못할 수 있다. 끝 여유 3 m 이상, 사람은 옆 4 m 밖. 제동 중 뒷바퀴가 잠길 수 있으므로 매끄러운 바닥에서는 속도 지령을 5 m/s로 낮춰 시작한다. 회생 한계가 −30 A처럼 크면 급제동이 세므로 손으로 차를 막지 않는다.

### T2. 저속 정상 원선회

- **목적**: 조향 이득 k와 언더스티어 K를 타이어 영향 없이 가른다(저속이면 K v² 항이 작다).
- **공간·준비물**: 바닥에 원을 그릴 필요는 없다. 반경은 조향으로 정해진다: R ≈ 휠베이스 0.33 m / tan(조향). 조향 0.1 → R 3.3 m(지름 6.6 m), 0.2 → 1.6 m, 0.25 → 1.3 m. 조향 0.1을 쓰려면 8 × 8 m, 0.15 이상만 쓰면 6 × 6 m.
- **주행 방법**: 속도 1.3 m/s(도구 문턱 0.7~1.8, 구간 시작 속도 1.0 이상이어야 하므로 중간값 권장). 조향 0.1, 0.2, 0.25 rad, **왼쪽·오른쪽 각각**.
  **오른쪽은 0.25 rad까지만.** 대회 차의 서보 창이 오른쪽 −0.254 rad이므로 0.30은 잘려서 0.254가 된다.

  ```bash
  ros2 topic pub -r 40 /drive ackermann_msgs/msg/AckermannDriveStamped \
    "{drive: {steering_angle: 0.2, speed: 1.3}}"      # 왼쪽 0.2.  오른쪽은 -0.2
  ```
- **길이·반복**: 조향 3단계 × 좌우 2방향 × 약 10 s(한 바퀴는 지름 3.3 m에서 약 8 s) = 약 1분. 여유 두고 약 3분.
- **합격 조건 (도구)**: 적용 조향 |값| > 0.08 rad, 속도 0.7~1.8 m/s, 요레이트 변화율 0.5 rad/s² 미만인 샘플이 **전체 합쳐 10 s(1000샘플) 이상**. 요약의 "못 잰 것" 목록에서 "조향 이득 k와 언더스티어 K의 분리" 줄이 사라지면 합격. 같은 시험에서 자이로 단위(곡선 구간 200샘플 이상)도 확정된다.
- **구간**: `T2 start/end` 표시가 있으면 그 구간의 샘플만 센다. **한계**: 도구는 이 조건을 **범위 검사로만 확인**하고 k와 K를 같이 맞춘다. 두 값이 실제로 갈라졌다는 검증(시험)은 저장소에 없다.
- **흔한 실수**: 속도 지령이 낮아 1.0 m/s 아래로 떨어짐. 오른쪽 0.30을 줌. 한 방향만 돎(좌우 비대칭 확인 불가).
- **안전**: 저속이라 위험은 적다. 원 둘레 장애물만 치운다.

### T6. 일정 조향 속도 램프 (미끄러질 때까지)

- **목적**: 최대 마찰의 **상한**과, 한계에서 앞이 밀리는지 뒤가 나가는지.
- **공간·준비물**: 10 × 10 m 이상 평평하고 장애물 없는 바닥. 둘레를 폼 보드 같은 부드러운 것으로 막거나 4 m 이상 비움. 영상 촬영(휴대폰 위에서). 배터리 완충 아니어도 됨.
- **주행 방법**: 조향을 0.25 rad로 고정(왼쪽·오른쪽 각각), 속도를 2 m/s에서 0.1 m/s씩 1초마다 올린다(권장). 이 조향이면 반경 약 1.3 m(운동학값)이고, 횡가속은 v²/R: 8 m/s²에 3.2 m/s, 10 m/s²에 3.6 m/s, 12.8 m/s²(마찰 1.3 g)에 4.1 m/s(권장 추정). 조향을 고정하면 반경이 커지는 것으로 앞이 먼저 미끄러지는지(언더스티어)를 영상과 궤적으로 본다. 스핀이나 반경이 크게 늘면 즉시 속도 지령 0.
  속도 램프는 명령 공백 없이 올려야 하는데 이를 만드는 발행기는 저장소에 없다. 지금은 2~3단계 계단(2.5, 3.0, 3.5, 4.0 m/s)을 `timeout 4 ros2 topic pub ...`로 이어 쓰되 단계 사이 공백을 감수하거나, 발행기를 먼저 만든다(8장).
- **길이·반복**: 한 번 약 25 s. 왼쪽 2회 + 오른쪽 2회, 총 약 100 s. 한 bag에 담되 20 s 블록이 2개 이상이어야 한다(아래).
- **합격 조건 (도구)**
  - 구간: `T6 start/end` 표시가 있으면 그립 하한·미끄러진 사건을 그 구간 안에서만 센다. (마찰·강성 판정은 재생 맞춤이라 bag 전체를 쓴다.)
  - 미끄러진 사건: 차체 미끄럼 변화(a_y/v − 요레이트의 적분)가 **1 s 안에 30° 넘게** 변하고 v > 2 m/s이며 충격이 없을 것. 요약의 `place.slides_seen`에 시각이 나오면 "못 잰 것"의 "최대 마찰(상한)" 줄이 사라진다. (기존 1쪽 절차서는 15°로 적었으나 코드는 30°.)
  - 마찰 판정 `mu_tyre_fit`이 "측정됨"이 되려면 "마찰 값 후보 격자(0.7~2.2) 양 끝이 모두 나쁘다고 판정"되어야 한다. 이 판정은 20 s 블록 단위 짝 검정이라 **블록이 2개 미만이면 오차가 무한대로 처리되어 판정이 안 난다**(코드상 그렇다). 또 재생 구간(2.5 s 창) 30개 이상. 그러니 T6 bag은 최소 40 s 이상, 가능하면 60 s 이상.
  - 그립 하한 `place.ay_max_held`가 10 m/s² 이상이면 한계까지 간 것이다(대회 bag 최대 9.7).
  - 한계에서 앞이 먼저인지 뒤인지는 도구가 판정하지 않는다(수동, 영상).
- **흔한 실수**: 미끄러지기 전에 램프를 멈춤 → 하한만. 램프가 너무 빨라 한계 직전 구간이 없음. 충돌해 충격 구간이 되어 그 구간이 버려짐. 한 방향만.
- **안전**: **가장 위험한 시험.** 차가 스핀하면 둘레로 미끄러져 나간다(반경 1.3 m에서 4 m/s면 이탈 거리 수 m). 사람은 10 × 10 m 밖, 보호 안경 권장. 조이스틱 확인 버튼을 쥐고 있다가 스핀하면 즉시 놓는다. 배터리 차는 충돌하면 손상될 수 있으니 둘레를 부드럽게. 처음엔 3.0 m/s까지만 올려 보고, 점차 올린다. 노면이 거칠면(고무 매트) 뒤집힐 수 있으니 바퀴가 걸리는 가장자리를 없앤다.

### T5. 조향 스텝·처프

- **목적**: 순수 지연과 서보 지연을 따로, 요 동특성.
- **공간·준비물**: 직선 20 m 또는 큰 원. 4 m/s에서 ±0.1 rad이면 요레이트 약 ±1.2 rad/s, 0.5 Hz에서 옆으로 약 0.5~1 m 움직이므로 폭 3 m 이상.
- **주행 방법**: 속도 2 m/s와 4 m/s 정속. 조향 ±0.1 rad 계단(0.5 Hz 사각파 10주기) 후, 조향 ±0.1 rad 사인 처프 0.5 → 4 Hz 5 s(기존 절차서 값). 오래된 연구실 절차서는 0.2 → 4 Hz 40 s였다. 처프 발행기가 필요하다. 저장소에 **없다**(8장). 조이스틱으로는 못 한다.
- **길이·반복**: 속도마다 계단 약 20 s + 처프 5 s, 3회.
- **합격 조건 (도구, 실차 미검증)**: `car.steer_tau_d`·`car.steer_tau_s`·`car.steer_tau_sum`. 조향 응답의 주파수 응답을 맞춘다. 입력은 적용 조향의 운동학 요레이트 수요 v·tan(δ)/L, 출력은 자이로 요레이트이고, 2.56 s 한 창씩 겹쳐 계산한 H(f)에 g·exp(−j2πfτd)/(1+j2πfτs)를 0.5~4 Hz에서 맞춘다. 구간은 `T5 start/end` 표시가 있으면 그것, 없으면 v > 1.5 m/s로 5 s 창 내내 달리고 1 Hz 이상 조향 성분의 rms가 0.02 rad 이상인 창을 모은 것(자동 인식). 판정(문턱값은 `CHIRP_*`):
  - 합격("분리됨"): 구간 합계 10 s 이상, 일관성 0.6 이상인 주파수 점 6개 이상, **입력 조향 성분이 2 Hz까지**(대역 최대 파워의 10 % 이상) 있고, 순수 지연 τd의 90 % 구간 폭이 30 ms 미만.
  - 아니면 `steer_tau_sum`(τd+τs)만 내고 τd, τs는 "식별 안 됨"("분리 식별 안 됨"). 구간이 10 s 미만이거나 점이 6개 미만이면 합도 "식별 안 됨".
  - τs에는 타이어·요 관성이 만드는 지연이 같이 들어간다(자이로가 보는 경로 전체의 1차 지연). 합성 신호(τd 0.05, τs 0.04 등)로만 시험했고 **실차로는 돌려 본 적이 없다**. 기존 단일트랙 재생 맞춤의 `actuator.cmd_delay`·`servo_tau`는 T5가 분리됨으로 판정되기 전에는 "식별 안 됨"(합만 정해짐)으로 표시된다.
- **흔한 실수**: 조향 진폭이 커서 서보 창에 걸림(잘림이 지연 판정을 망침). 주파수가 낮아 위상 차이가 안 보임.
- **안전**: 한계 근처 횡가속이 되지 않게(조향 0.1이면 4 m/s에서 약 5 m/s²).

### T4. 코스트다운

- **목적**: 구름·공기 저항.
- **공간·준비물**: 직선. 필요한 거리는 **알 수 없다**: 시뮬 기본 저항(구름 0.1 m/s², 공기 0.01 v²)이 맞다면 5 m/s에서 감속이 약 0.35 m/s²라 완전히 서기까지 수십 m(권장 추정으로 40~60 m)가 필요하다. 직선 15~20 m이면 5 → 3 m/s 구간만 굴린다.
- **주행 방법**: 속도 5 m/s까지 올린 뒤 **전류 0**으로 굴림. 속도 지령 0은 회생 제동이 걸려서 코스트다운이 아니다(`/sensors/core` 전류로 확인). 전류 0을 어떤 토픽으로 내는지는 (미검증): VESC 드라이버의 `/commands/motor/current`에 0을 내는 방식이 일반적이나 이 차의 드라이버 버전을 먼저 확인한다. 조이스틱·`/drive` 속도 지령으로는 못 한다.
- **길이·반복**: 한 번에 5 → 2.5 m/s 구간, 2회(왕복).
- **합격 조건 (도구, 실차 미검증)**: `car.coast_c0`(구름, m/s²), `car.coast_c2`(공기, 1/m). 감속 = c0 + c2·v². 구간은 `T4 start/end` 표시가 있으면 그것, 없으면 |모터 전류| ≤ 0.5 A, v ≥ 0.5 m/s, 속도 지령 < 바퀴 속도가 1 s 이상 이어지고 속도가 0.2 m/s 넘게 줄어든 구간(양 끝 0.1 s는 버림). 판정(`COAST_*`): 구간 2개 이상, 합계 3 s 이상, 속도 폭(5~95 %) 2 m/s 이상이면 "측정됨"(오차는 구간 단위 부트스트랩 5~95 %). 모자라면 "식별 안 됨"이고 무엇이 얼마나 모자랐는지 숫자로 적힌다. 합성 신호로만 시험했고 실차 미검증이므로 `vehicle.c_roll`·`c_drag` 출력은 `apply: false`로 나온다(확인 뒤 사람이 켠다).
- **흔한 실수**: 속도 0 지령으로 정지(회생 제동). 경사 상쇄를 안 함(왕복 필요). 전류 0이 안 되는 VESC 설정.
- **안전**: 끝에서 서지 않을 수 있다. 3 m/s에서 속도 지령 0으로 마무리.

### T7. 레이스 랩 5바퀴 이상 (검증 전용)

- **목적**: T0~T6으로 맞춘 프로필이 실제 주행을 0.5/1/2 s 앞까지 잘 예측하는지.
- **공간·준비물**: 레이스 트랙. 평소 레이스 노드.
- **주행 방법**: 평소대로. 앞뒤 정지 5 s.
- **길이**: 5바퀴 이상(약 3분). 재생 구간 30개 이상이 필요한 것은 같음.
- **합격 조건 (도구)**: `--car <프로필>`로 돌리면 요약의 "재생 오차" 표에 `car_profile` 줄이 나온다(맞춘 값이 아닌 프로필 그대로의 예측 오차, 표본 밖). 대회 차·대회장에서 1 s 요레이트 오차 약 0.12~0.15 rad/s였다(REPORT.md). 이 수준이면 합격으로 본다(권장).
- **흔한 실수**: 같은 bag으로 맞추고 같은 bag으로 검증(표본 안 오차).
- **안전**: 평소 레이스와 같음.

**한 번의 약한 근거**: 사전 장소 마찰 약 1.0(스핀 1건, 7월 27일 bag).
**없는 값**: 최대 마찰 상한, 타이어 곡선 모양, 구름·공기 저항(추정기는 생겼으나 코스트다운 녹화가 없다), 질량·무게중심·요 관성(입력 경로는 생겼으나 잰 값이 없다), 조향 이득의 절댓값(같음), 순수 지연 대 서보 지연의 분리(처프 녹화가 없다), 한계에서 앞·뒤 중 먼저 빠지는 쪽. 레이스 주행 bag만으로는 이 값들이 안 나온다. 그립 정보는 횡가속 8 m/s² 이상 구간에만 있다.
**대회 차로 사전 장소를 달린 bag 없음**: 합친 기본 프로필(대회 차 값 + 사전 장소 값)을 직접 검증할 bag이 없다.

**다음에 차를 쓸 수 있을 때 가장 먼저 찍을 것**

1. **T1 + 바퀴 각 실측(30분 이내, 정밀 세트 A4)**: 조향 이득이 명령보다 약 1.6배 작게 나오는 문제가 절댓값 없이 남아 있다. 이 값이 정해져야 이후 모든 조향 분석의 단위가 정해진다. 가장 비용 대비 효과가 크다.
2. **T6 속도 램프**: 그립은 하한(0.8~1.0 g)만 있고 상한이 없어 시뮬의 마찰 범위(0.70~1.10)와 한계 주행 학습이 근거 없는 가정에 있다. 5분이다.
3. **대회 차로 사전 장소에서 레이스 랩(T7)**: 합친 기본 프로필의 직접 검증. 새로 만들 코드 없이 평소 주행만으로 된다.
4. **T2 저속 원선회**: k·K 분리. 노면·타이어가 바뀌면 강성 값이 달라지므로 새 노면에서는 T2와 T7을 같이.
5. **T4 코스트다운과 T5 처프**: 저항과 지연 분리. 코스트 구간이 많은 전략을 학습하기 전까지는 미뤄도 된다. 추정기는 있으나 실차 미검증이고, 시험 명령 발행기가 먼저 필요하다(8장).

### 8.2 값이 읽히는 것보다 약한 곳

- `tau_d`와 `tau_s`(기존 재생 맞춤 값, `actuator.cmd_delay`·`servo_tau`)는 T5 처프가 "분리됨"으로 판정되기 전에는 상태 "식별 안 됨"으로 찍히고 합만 정해진 값이다.
- `lidar.mount_x`, `mount_z`는 `/tf_static`에 적힌 설정값이라 출처 "설정값(규격)", 상태 "식별 안 됨"이다. 실측은 `hand_measured.lidar_mount_m`.
- 구동·회생 전류 한계는 평평한 구간이 확인될 때만 "측정됨"이고 아니면 "하한만"이다. 평평한 구간이 있어도 그 값이 설정 한계라는 보장은 없다(예: 전압 강하로 낮아진 한계). `setup.yaml` 대조가 이를 잡는다.
- 한 bag의 마찰·강성 판정은 구간 수가 적으면 흔들린다(보고서). 장소 단위로 묶어서 볼 것. 실제로 같은 bag을 도구 수정 전후로 돌리면 재생 구간이 하나 달라지는 것만으로 마찰 하한 격자 점이 한 칸(1.3 → 1.5) 움직이고 속도 루프 시간 상수가 20 % 넘게 바뀐다.
- 새 추정기 두 개는 실차 데이터가 없다. 합성 신호(알려진 값 + 잡음)로 값이 돌아오는지만 시험했다. 실차에서는 τs가 타이어·요 관성의 지연을 포함하고, 코스트다운은 바퀴 속도의 도함수라 ERPM 양자화와 바닥 경사에 민감할 수 있다(미검증).
- 대회 bag(fastest-longest, 자동 인식)에서 두 추정기는 각각 "코스트다운 식별 안 됨(전류 0.5 A 이하로 1 s 넘게 줄어든 구간 없음)", "조향 응답 합만 냄(입력이 2 Hz까지 안 감)"이었다. 레이스 주행으로는 안 나온다는 기존 판단과 같다.

### 8.3 정해진 주행을 일정하게 내는 명령 스크립트: 저장소에 없다

`f1sim_ros/`(`teleop_node.py`는 조이스틱·키보드 운전 노드이고 시뮬레이터 중심이며 현재 수정 중, `vesc_sim_node.py` 등은 시뮬레이터용)와 `scripts/`(`gen_sim_bags.py`, `replay_traction.py`, `wheelslip_compare.py`는 시뮬레이터·분석용)를 확인했다. 계단, 처프, 코스트다운, 일정 반경 속도 램프, 풀가속 후 제동을 정해진 값으로 내는 코드는 없다(코드 검색에서 `chirp`, `coastdown`, `skidpad` 등이 나오는 곳은 `bag_profile/report.py`의 안내 문구뿐). **실차를 움직이는 코드는 이번에 새로 만들지 않았다.**

**만들어야 할 것** (우선순위순)

1. **시험 명령 발행기**: 정해진 순서(조향 계단, 속도 램프, 풀가속 후 제동, 조향 처프, 전류 0 코스트다운)를 40 Hz 이상 끊김 없이 `/drive`(또는 중재기가 받는 토픽)에 내고, 시작·끝에 `/sysid/segment`를 자동으로 낸다. 안전장치: 속도 상한, 시험별 최대 시간, 조이스틱 확인 버튼 해제 시 즉시 정지, 시작 전 명령 중재기 확인.
2. **실차 검증**: 코스트다운 추정기와 처프 분석기를 실차 녹화로 돌려 합성 시험의 값과 비교(지금은 합성 시험만).
3. **일정 반경 램프 분석기**: 곡률과 속도로 구간을 자르고, 앞·뒤 먼저 미끄러지는 쪽과 최대 마찰 상한을 낸다.
4. **현장 한 줄 판정**: 통과/재촬영을 한 화면에 표시하고, "한계 전류에 닿았는가"를 설정값으로 판정.
