## 4. 사후 분석 (등록 밖)

S4·S5·S6은 같은 두 스크립트의 옵션(`--ego raw`, `--linear-horizon 0.6 --no-certify`, `--min-step 40`)으로 돌렸습니다. S3은 저장소 밖 진단입니다.
- S3a: guard의 `_candidates`를 두 형식의 spec으로 뽑아, 캡처한 추종기 입력으로 `mpc.solve`를 풀었습니다.
- S3b: `InteractiveTeacher._stop_speeds`를 wp4에서도 −1을 돌려주도록 바꾼 채 `wp4_label_replay.py`를 실행했습니다.

**S3a. guard 감속 후보의 실행 제동.** ICCAS에서 wp4 guard가 방문한 상태 중 3 m/s 이상인 4842개에서, 같은 추종기 입력으로 비교했습니다. 칸은 첫 가속 [m/s²] / v_cmd − v [m/s] / 창 끝 속도 − v [m/s]입니다.

| 후보 | wp4 | linear |
|---|---|---|
| ×1.0 | +0.92 / +0.19 / +0.41 | −0.08 / +0.00 / −0.04 |
| ×0.8 | −1.16 / −0.21 / −0.59 | −1.43 / −0.24 / −0.64 |
| ×0.55 | −3.26 / −0.57 / −1.73 | −3.58 / −0.58 / −1.70 |
| ×0.3 | −4.44 / −0.67 / −2.44 | −4.72 / −0.68 / −2.42 |
| 정지 | **−2.91** / −0.57 / −2.09 | **−5.00** / −0.70 / −2.79 |

- 속도 배율 후보는 두 형식이 거의 같습니다.
- wp4의 정지(a_brake 제동 곡선, 설계 5절)는 추종기의 속도 지연(q_v 0.4) 때문에 곡선의 60 %만 실행됩니다. 그래서 자기 ×0.3보다 약합니다.
- ×1.0이 가속하는 것은 wp4 라벨에 인증이 없고, 프로파일을 경로점에서 읽기 때문입니다.

## 5. 해석

- **형식 자체는 같은 페이스에서 linear보다 낫습니다.** 열린 루프 관문(편향, 조향 잡음, 저속 권한)과 같은 페이스 비교(S4, S6)가 그렇게 말합니다.
- **생산 라벨끼리 비교하면 wp4가 더 빠르고, 그만큼 더 닿습니다.**
  - linear 생산 라벨은 인증과 1.5 s 끝점 때문에 일찍 늦춥니다(설계 4절 표의 0.5 s).
  - wp4 라벨은 설계대로 그 둘을 뺐습니다.
  - 시험 4b·6의 실패는 이 페이스 차이를 접촉율로만 잰 결과입니다. 시험 4b는 설계가 "같은 페이스"를 전제한 시험인데, guard 아래에서는 그 전제가 무너집니다.
- **교통(시험 3)은 형식 문제와 정지 후보 문제가 섞여 있습니다.**
  - lane_switch 초과분의 절반은 정지 후보입니다(S3b).
  - interactive 상대와의 초과(6배)는 정지로 설명되지 않습니다. 남은 후보는 둘입니다. wp4 ego가 더 빠르다는 점(+3.6 %), 그리고 그 env에서는 상대 interactive 교사도 wp4로 계획한다는 점입니다. 이 실행으로는 둘을 가르지 못했습니다.
- **forzaeth_pred의 κ1 점프 1.48 %**는 linear 자신도 1.12 %인 조건입니다. 1 % 기준은 이 측정 정의로는 linear도 넘습니다.

## 6. 남은 일과 제안 (다음 단위)

1. **정지 후보.** 설계 5절의 "a_brake 감속 프로파일"은 실행에서 linear 정지의 60 %입니다.
   - 추종기가 실제로 낼 수 있는 가장 센 제동(−1, 실행 −4.9 m/s²)으로 바꿀지 결정이 필요합니다. 라벨 정직성(설계)과 제동력(측정)이 부딪힙니다.
   - 바꾸면 시험 3을 다시 돌립니다.
2. **시험 3·4b·6의 비교 기준.** 생산 linear(느림)와 비교할지, 같은 페이스 linear와 비교할지 정해야 합니다. 등록된 판정은 생산 기준으로 실패입니다.
3. **interactive 상대와의 초과 접촉.** ego 형식과 상대 형식을 나눠 재는 실험이 필요합니다. 지금 env는 행마다 추종기 형식을 고를 수 없습니다(리그 where, 이주 6단계).
4. 이주 4~8단계: 학습 코드(디코드 공간 손실, PPO 차원별 log_std, kl_scope), 콘솔·뷰어, 리그 where, Plan.msg format, arm 포팅. `learn/maneuver.py`의 offset_candidates/offset_plan도 linear 전용입니다(decode/encode).
