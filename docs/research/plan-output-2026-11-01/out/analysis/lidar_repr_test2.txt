LiDAR 입력 표현 시험 2 (11-25 오후) -- net_redesign_v2.md §5의 첫 반증 시험 + 추가 시험 '움직이는 차와의 시간 맞춘 빈틈'
==========================================================================================================

무엇을 시험했나 (기록은 오전 시험과 같은 것: 1대1 r4a/b/c 384 세션 x 90 s, 혼자+상자 l3a/b 256 세션 x 60 s; 같은 나눔·같은 예산)
  1. 점 토큰 앞단 (설계 A/C): 마지막 5장(또는 10장) 스캔의 모든 점을 거리계 사슬로 지금 틀에 정확한 좌표로 옮기고(격자 없음), 빔 8개
     (가장 새 장) / 16개(이전 장)씩 묶어 토큰 약 400개(10장: 748개). 점마다 Fourier(x, y; 0.05/0.2/1/5 m) + 나이 + 거리 -> MLP -> 묶음마다
     max. 시간 맞춘 plan query 10개(앞 plan의 점을 지금 틀로 옮긴 자리) + 차 query 1개, 키·값에 상대 위치 Fourier(토큰 - 기준점)와 나이,
     블록 2개 [query -> 토큰 cross-attention, query끼리 self-attention, FFN], 폭 128, head 4, 토큰끼리 attention 없음. 출력은 오전 상대 차
     시험과 같은 21개 (상대 차 0.1..1.0 s 10점 + '있음').
  2. plan 점의 빈 공간 정밀도 (새 시험): 이 결정이 그린 plan의 10점에서 가장 가까운 상자 모서리(기록의 상자 발자국·자세)와 벽(벽 기준
     거리장, 1.25 cm 격자, 쌍선형)까지의 부호 있는 틈, [-0.5, 2] m로 자름. 혼자+상자 기록, 상자 배치로 나눔(따로 둔 배치 12개).
     모형 4개: 지금 방식(극좌표 + GRU, 묶은 벡터 + 점 좌표), 격자 10장 묶은 벡터 + 점 좌표, 같은 격자 CNN을 plan 점에서 쌍선형으로
     읽기(0.25 / 0.5 / 1 m 특징 지도), 점 토큰 5장(query를 plan 점에).
     주의: 기록의 plan 점은 k = 1에서만 실제 자리와 같음(0.4 cm). 차가 매 결정 다시 그리므로 k = 5에서 7.7 cm, k = 10에서 29 cm 다름 ->
     타깃은 '그 시각 실제 자세'가 아니라 plan 점 자체(§5가 뜻한 'plan 자신의 점').
  3. 움직이는 차와의 시간 맞춘 빈틈 (추가): 1대1 기록, 상대 차가 '있음'인 결정마다 k = 1..10에 대해, 0.1 k s 뒤 우리 차(그 시각
     실제 자세)와 같은 시각 상대 차 사이의 부호 있는 틈. 두 차 모두 0.58 x 0.31 m 상자, 정확한 상자-상자 거리(떨어져 있으면 꼭짓점-상자
     최단 거리, 겹치면 분리축 겹침의 최소를 음수로; 3원판 근사는 안 씀; 무작위 300쌍에서 무차별 계산과 0.07 mm 안), [-1, 3] m로 자름.
     query = 그 시각 우리 자세(지금 틀의 x, y, 방향 cos·sin) -- 실제 자세라서 plan과는 k ≥ 2에서 조금 다름. 재시작·상대 순간이동 사이 칸은
     뺌. 모형: 점 토큰 5장, 격자 10장 쌍선형 읽기, 지금 방식(극좌표 + GRU). 참값 기준: 상대가 지금 자리에 그대로 / 지금 자리 + 참 속도로 직진.
  4. 숨은 상자, 점 기억 갈래: 1024점 점 기억, 거리계 증분으로만 옮김(스캔에 다시 맞추지 않음), 가장 새 스캔을 빔 8개마다 하나씩 FIFO로
     씀, 학습되는 점수 없음; 오전 격자 기억과 같은 U-Net·같은 채점. 1x 잡음으로 학습, 0 / 0.5 / 1 / 2x로 평가.
     + 진단 갈래 하나(사양 밖): 같은 1024점에 '0.15 m 안에 이미 점이 있으면 그 점을 새로 갱신, 아니면 FIFO' -- 이유: 사양 그대로의 FIFO는
       한 장에 점 ~110개라 1024점이 0.9 s밖에 못 담아, 한 바퀴(7 s) 전 상자를 처음부터 담을 수 없음. 장치(점 집합) 자체가 되는지 보려면
       담는 규칙이 공간을 기준으로 해야 함(격자 기억이 칸마다 덮어쓰는 것과 같은 일, 여전히 학습 없는 기하 규칙).

결론 먼저
  (1) 상대 차 1 s 위치: 점 토큰은 통과 못 함. 
      * 1.0 s 뒤 중앙 / p90: 점 토큰 5장 0.46 / 1.37 m, 잡음으로 학습·평가 0.45 / 1.34 m -- 격자 10장 0.34 / 1.03 m, 지금 방식 0.50 / 1.73 m.
        통과선 셋 다 못 넘음: 전체 0.46 > 0.34 m, 느린 상대(< 0.7) 0.59 > 0.39 m, 6-10 m 0.83 m로 격자(0.51 m)보다 0.32 m 나쁨(먼 차의 토큰이
        드물다는 §3의 우려가 맞음). 0.5 s 뒤 0.30 / 0.94 m(격자 0.21 / 0.66).
      * 지금 위치(0.1 s 점)부터 0.21 m로 격자(0.16 m)보다 나쁘고, 위치를 뺀 움직임만의 오차도 0.45 m(격자 0.33 m) -- 점이 정확해도 나이가 다른
        토큰끼리 비교할 길이 11개 query의 cross-attention뿐(토큰끼리 attention 없음)이라 움직임을 덜 뽑는 것으로 봄(추정, 따로 재지 않음).
      * 거리계 잡음에는 강함: 참 자세로 학습한 것을 잡음 자세로 읽어도 0.46 m 그대로.
      * 점 토큰 10장은 랩 우선 작업(orc34a 관문 시험) 때문에 20 epoch 중 8 epoch에서 멈춤(조정자가 중지): 그때 0.58 m(같은 epoch의 5장 0.63 m,
        격자 10장 0.47 m) -- 끝 값 없음, 판단에 안 씀.
      * §5의 읽기대로: 점 앞단은 움직임 이득이 없음 -> 상대 차 위치에는 B(격자 + 점에서 읽기)로 돌아감. 단 (3)을 보면 그 결론은 "상대 위치를
        맞히는 일"에 한함.
  (2) plan 점의 빈 공간: 정밀도는 '읽는 방법'이 정함.
      * 점 토큰 5장: 상자 3.2 cm 중앙(p90 14.6), 상자 틈 < 0.3 m에서 3.3 cm, 지금 보이는 상자만 2.9 cm; 벽 1.0 cm(< 0.3 m에서 1.0 cm).
        통과선(중앙 ≤ 3 cm, < 0.3 m에서 ≤ 5 cm): 벽 통과, 상자는 < 0.3 m 칸 통과·전체 중앙 3.2 cm로 0.2 cm 넘음(보이는 상자만이면 2.9 cm).
      * 같은 격자 CNN을 plan 점에서 쌍선형으로 읽으면 상자 3.9 cm(< 0.3 m 3.1 cm), 벽 1.6 cm -- 점 토큰과 1 cm 안(§5의 읽기: 정밀도는
        읽는 방법으로 풀리고, 현재 입력은 격자여도 됨 -> 비용으로 고름). 단 상자 < 0.3 m 칸의 p90은 점 토큰 28.8 cm, 격자 쌍선형 10.1 cm로
        점 토큰의 꼬리가 더 큼.
      * 격자를 한 벡터로 묶으면 상자 7.2 cm(< 0.3 m 8.7), 벽 3.3 cm = 쌍선형 읽기의 약 2배 -> 초안의 '펼쳐서 256개로'가 손실이었음.
        지금 방식(극좌표 + GRU)은 상자 9.3 cm(< 0.3 m 11.6, p90 78 cm), 벽 3.4 cm.
  (3) 움직이는 차와의 시간 맞춘 빈틈: 여기서는 점 토큰 + 시간 맞춘 query가 분명히 이김.
      
      * 상대가 0.5 m 안인 칸(점 19020개, 그중 겹침 552개)의 틈 오차 중앙 / p90: 점 토큰 7.3 / 31.4 cm, 지금 방식 11.2 / 70.9 cm, 격자 쌍선형
        13.7 / 86.7 cm. 상대가 3 m 안인 칸 전체: 9.3 / 43.5, 13.3 / 61.1, 13.5 / 62.3 cm. 참값으로 만든 "상대 지금 자리 + 참 속도로 직진"도
        3 m 안 17.5 / 71.9 cm, 0.5 m 안 13.7 / 56.2 cm -> 점 토큰은 참 위치·참 속도를 아는 직진 외삽보다 나음.
      * 페이스별 (3 m 안 중앙; 0.5 m 안 중앙): < 0.7 점 토큰 13.4; 7.6 / 지금 방식 19.0; 12.3 / 격자 20.0; 12.9 cm, 0.7-0.9 7.5; 6.8 /
        10.5; 8.6 / 11.6; 15.9 cm, ≥ 0.9 9.9 / 14.9 / 11.9 cm (빠른 상대와는 0.5 m 안으로 가까워진 칸이 없음).
      * 부호(겹침 대 틈), 0.5 m 안: 맞은 몫 95.3 / 96.2 / 95.7 % -- 그러나 겹침이 이 칸의 2.9 %뿐이라 "늘 틈"이라고만 해도 97 %. 실제 겹침 중
        겹침으로 맞힌 몫 15.0 / 7.4 / 4.7 %, 틈인데 겹침이라 한 몫 2.3 / 1.1 / 1.6 %: 셋 다 접촉 자체는 거의 못 맞힘(드문 사건).
      * 정리: 상대 "위치"(1)는 격자가 이기고, 우리 plan 시각·자리의 "빈틈"(3)은 시간 맞춘 query가 이김(0.5 m 안 중앙이 지금 방식보다 35 %,
        격자보다 47 % 작음). query는 "내 점 근처에 무엇이 있나"를 묻는 구조라 (3)이 그 설계의 시험이고, 거기서는 통과에 해당.
  (4) 숨은 상자: 격자 기억이 그대로 감.
      * 사양 그대로의 점 기억(FIFO 1/8, 1024점): 1x 잡음에서 재현율 0.28 · 정밀도 0.19 -- 기억 없는 바닥선(0.16 · 0.14) 근처. 1024점이
        0.9 s치밖에 못 담는 용량 문제(위 4.의 설명), 잡음 0에서도 0.30 · 0.19.
      * 진단 갈래(0.15 m 안 갱신 + FIFO): 0x 0.90 · 0.86, 0.5x 0.84 · 0.80, 1x 0.73 · 0.68, 2x 0.46 · 0.40 -- 격자 기억(1x 0.78 · 0.72,
        0x 0.87 · 0.88)과 비슷하나 1x에서 통과선(0.78 · 0.72)에 조금 못 미침. 점 집합도 '공간 기준으로 덮어쓰기'를 하면 되지만 격자보다
        낫지 않음 -> 격자 기억 유지.
