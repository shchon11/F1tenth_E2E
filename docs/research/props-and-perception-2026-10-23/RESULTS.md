# 장애물 충돌, 평가 조건, 정책이 아는 것 (2026-10-23)

`car-contact-anatomy-2026-10-23`의 후속입니다. 두 가지를 물었습니다.

- v2의 강한 충돌이 v1보다 많은 이유는 무엇인가(벽·장애물).
- 차 충돌은 정책이 몰라서 나는가, 알면서 나는가.

## 1. 벽·장애물 강한 충돌의 해부 (`tools/wall_prop_anatomy.py`)

조건은 최종 평가의 경주 칸과 같습니다. 시드 81–82, 상대 4종이고, 기록 수는 측정기와 칸마다 같습니다.

| | v2 대회용 | v1 대회용 |
|---|---|---|
| 강한 장애물 / 강한 벽 (km당) | 1.34 / 0.17 | 0.59 / 0.26 |
| 장애물 충돌 부위 | 앞면 47/47 | 앞면 20/20 |
| 직전 1 s에 상대 차 1.5 m 안: 있음 / 없음 (km당) | 0.74 / 0.60 | 0.38 / 0.21 |

- v2가 v1보다 강한 충돌이 많은 이유는 장애물입니다(2.3배). 차와 벽은 v2가 더 적습니다.
- 처음에는 '밀려 움직이는 장애물에 맞았다'는 가설을 세웠지만 틀렸습니다.
  - 충돌 직전 우리 차 속도(중앙값 3.3 m/s)가 충돌 속도(2.8 m/s)보다 큽니다. 서 있는 장애물을 앞면으로 친 것입니다.

## 2. 장애물 접근 (`tools/prop_approach.py`)

**접근의 정의.** 살아 있는 장애물의 중심이 차 앞 6 m 안이고 |y| < 0.45 m인 구간입니다. 곧장 가면 닿는 경우입니다.

**혼자 주행 + 경주와 같은 장애물** (32대 × 60 s × 시드 2)

| | 접근 | 강한 충돌 | 약한 충돌 |
|---|---|---|---|
| v2 | 1,504 (18.5 km) | **0** | 3 |
| v1 | 1,476 (17.8 km) | **0** | – |

두 정책 모두 혼자서는 장애물을 완벽하게 피합니다.

**경주** (상대 4종 × 시드 2)

| | v2 | v1 |
|---|---|---|
| 접근 / 강한 충돌 | 2,982 / 37 (1.2 %) | 3,045 / 18 (0.6 %) |
| 상대 차의 장애물 접촉 / 강한 접촉 (상대 차 km당) | 33.0 / 9.1 | 33.0 / 8.9 |
| 강한 충돌 접근: 장애물이 진로에 들어온 시점 (도달까지 s) | 0.56 | 0.56 |
| 무사 통과 접근: 같은 값 | 0.91 | 0.94 |
| 강한 충돌 접근 중 원래 자리에서 0.2 m 넘게 밀려난 장애물 | 78 % | 44 % |
| 강한 충돌 접근에서 감속함 / 핸들로 피함 | 92 % / **8 %** | 100 % / **28 %** |

- **상대 차가 장애물을 계속 밀어 놓습니다.** 상대 플래너는 `ProceduralObstacles.clearance`로 장애물을 '보지만' 피하지 못하고, km당 33번 닿고 9번은 강하게 칩니다.
  - 경주 평가는 `--procedural-raceline-corridor off`로 장애물을 경주 라인 위에도 놓습니다.
  - 그래서 밀려난 장애물이 늦게(0.56 s 전) 우리 진로에 들어옵니다.
- **0.56 s로는 제동만으로 못 섭니다.** 4.2 m/s에서 구동계 지연 0.2 s가 있기 때문입니다.
  - v1은 그런 경우 28 %를 핸들로 피했고, v2는 8 %만 피했습니다.
  - v2의 남는 약점은 갑자기 나타난 장애물을 핸들로 피하는 것입니다.

## 3. 장애물을 경주 라인 밖에 두면 (`tools/corridor_on_gpu1.sh`)

장애물 배치의 기본값은 라인 밖(`--procedural-raceline-corridor on`)입니다. 장애물 코드에 이유가 적혀 있습니다. 다른 차들이 장애물을 제대로 못 보기 때문입니다. 아래는 같은 경주 칸을 이 조건으로 돌린 결과입니다.

| 강한 충돌/km | 차 | 벽 | 장애물 | 합 | 경주 속도 | 추월/분 |
|---|---|---|---|---|---|---|
| v2, 장애물 라인 위 | 0.88 | 0.17 | 1.37 | **2.42** | 4.57 | 0.84 |
| v2, 장애물 라인 밖 | 0.84 | 0.00 | 0.22 | **1.07** | 4.64 | 0.63 |
| v1, 장애물 라인 위 | 1.14 | 0.26 | 0.59 | **1.99** | 4.44 | 0.73 |
| v1, 장애물 라인 밖 | 1.36 | 0.20 | 0.15 | **1.71** | 4.49 | 0.55 |

- **평가 조건 하나로 결론이 뒤집힙니다.**
  - 장애물이 라인 위면 v2가 v1보다 강한 충돌이 많습니다(2.42 대 1.99).
  - 라인 밖이면 v2가 38 % 적습니다(1.07 대 1.71).
  - 지금까지의 경주 표는 라인 위 조건입니다. 강한 충돌 열에는 상대 차가 밀어 놓은 장애물에 대한 반응이 크게 섞여 있습니다.
- **차 충돌은 두 조건 모두 v2가 적습니다.** 라인 위 0.88 대 1.14, 라인 밖 0.84 대 1.36입니다.
- **추월은 라인 위에서 많습니다.** 장애물에 걸려 상대가 느려지기 때문입니다.

## 4. 정책은 차 충돌이 오는 것을 아는가 (`tools/contact_probe.py`, `contact_probe_analyze.py`)

**자료.** 경주 칸에서 학습 차와 상대 차의 중심 거리가 3 m 안인 모든 순간입니다. 시드 81로 맞추고 시드 82에서 평가합니다.

- v2: 맞춤 45k / 양성 300, 평가 39k / 양성 320
- v1: 맞춤 46k / 양성 440, 평가 양성 380

**정답.** 0.5 s 안에 강한 차 충돌이 시작되는가입니다.

| | v2 대회용 | v1 대회용 |
|---|---|---|
| 선형 탐침 AUC: 실제 상대 상태(거리, dx, dy, 다가오는 속도, 옆 속도, 두 차 속도) | 0.960 | 0.947 |
| 선형 탐침 AUC: 정책 내부 특징 | **0.900** | **0.753** |
| 선형 탐침 AUC: 거리 하나만 | 0.761 | 0.808 |
| 특징 → 실제 다가오는 속도 R² | 0.65 | 0.33 |
| 특징 → 실제 상대 옆 속도 R² | 0.75 | 0.54 |
| 특징 → 실제 거리 R² | 0.80 | 0.31 |

- **v2의 상태는 차 충돌 위험을 대부분 압니다.**
  - AUC 0.90으로, 실제 상태 0.96에 가깝습니다.
  - 다가오는 속도와 옆 속도도 담고 있습니다.
  - v1(라이다 6장)보다 훨씬 잘 압니다. 재설계의 보조 출력(가장 가까운 차, 상대 슬롯)이 만든 차이로 보입니다.
  - 다만 v2의 '가장 가까운 차' 출력 자체의 다가오는 속도 값은 R² 0.005로, 잘못 맞춰져 있습니다.
- **그런데 행동은 이 정보를 쓰지 않습니다.**
  - 충돌 0.5 s 전에도 가속 중입니다(77 %).
  - 비용을 0.75 m/s부터 매겨도(`v2PHs_s2424`, 256 회) 차 접촉은 그대로였습니다. 같은 변경으로 벽·장애물 강한 충돌은 30 % 줄었습니다.
  - 따라서 차 충돌의 병목은 인식이 아니라 학습(신호 또는 보상의 저울질)입니다.

## 열린 질문

1. **경주 평가에서 장애물을 어디에 둘 것인가.** 사용자 결정이 필요합니다.
   - 라인 위에 두면 상대 차가 계속 밀어 놓습니다. 강한 충돌 수치를 지배하고 결론을 바꿉니다.
   - 라인 밖에 두면 장애물 코드의 설계 의도대로입니다.
   - 둘 다 보고하는 것도 방법입니다.
2. **v2의 늦게 나타난 장애물 회피.** 핸들로 피하는 비율이 8 %로 v1의 28 %보다 낮습니다. 원인은 아직 모릅니다.
3. **차 충돌에서 아는 것과 하는 것의 차이.** 학습 신호의 문제입니다. 후보는 이득 추정이 충돌 직전 행동을 벌하는지(어드밴티지 부호), 학습률·기간, 보상 대 비용의 크기입니다.
