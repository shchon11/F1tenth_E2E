## 0. 결론 먼저

1. **RL이 실제로 고르는 행동은 "다음 0.1초의 조향각과 속도" 두 숫자뿐이다 [확인].** 출력은 1초짜리 궤적(10점)이지만, 나머지 18개 출력은 RL로 최적화되지 않고 "실제로 차가 간 길"을 따라 그리도록 지도학습되는 예측이다. 강화학습 관점에서 이 시스템은 "10 Hz 직접 제어기 + 자기 경로 예측기"다.
2. **학습 중 차는 동역학이 아니라 운동학 자전거 모델로 '계획대로 정확히' 움직인다 [확인].** 미끄러짐·지연·추종 오차가 없다. 정기 시험도 모두 이 조건이다 [확인]. 실제 배치 경로(MAP 추종기 + 동역학)로 최근 체크포인트를 시험한 기록은 없다 [확인]. 그 차이는 바퀴 시간 5–7 % 정도라는 커밋 기록이 있다 [주장].
3. **학습은 약 250 update(약 5천만 결정)에서 사실상 멈췄다 [확인].** 그 뒤 2.3억 결정(약 6,500 차-시간)을 더 써서 바퀴/분은 7.45→7.61(+2 %)뿐이다. 설정을 바꾼 다른 실행들도 모두 7.4–7.6 바퀴/분, 5.2–5.3 m/s에 멈춘다 [확인].
4. 멈춘 이유는 세 가지가 겹친 것으로 본다.
   - (a) **탐색이 0.1초 깊이다.** 학습 잡음이 실제 주행선을 옮기는 폭은 중앙 0.18 m, 0.5 m 넘는 경우는 1 %다 [계측]. 탐색 표준편차는 하한에 붙어 학습되지 않는다 [확인]. 속도 출력은 45 %의 결정에서 tanh가 포화돼 탐색이 사실상 0이다 [계측].
   - (b) **정책 gradient의 신호 대 잡음이 1 정도다.** 잡음 규모(B_noise) 15만–60만 결정이 한 rollout(39만 결정)과 같은 크기다 [확인]. 그래서 actor는 update당 Adam 4걸음만 간다 [확인].
   - (c) **대전 목표가 추월을 손해로 만든다.** 내 책임의 강한 차 접촉은 return을 끊어 약 2.5–3.3바퀴의 가치를 잃는다 [추정·계산]. 추월 보상은 없고, 학습 상대는 자기 복사본뿐이며, 상대 차가 있는 판은 30 %다 [확인]. 결과: 0.6배속 상대는 들이받고(내 책임 접촉 3.9회/90초 세션), 0.8배속 상대는 거의 못 앞지르고(0.22회), 0.95배속 이상 상대는 전혀 못 앞지른다 [확인, 시험 결과].
5. 단독 주행 속도는 **이 운동학 모델 안에서는 이미 한계 근처**일 가능성이 크다. 같은 주행선을 모델 한계까지 쓰는 이론 바퀴 시간이 7.03 s로, 실제 7.30 s보다 3.7 % 빠를 뿐이다 [계측, 근사]. 남은 이득은 (i) 다른 주행선을 찾는 것(탐색 문제), (ii) 시뮬과 실차의 차이를 줄이는 것에 있다.
6. 이전 개발자의 "충분하다"는 판단에 대해:
   - 단독 + 상자, **계획대로 정확히 실행하는 조건**에서는 대체로 맞다 (빈 트랙 7.10 s, 세게 닿음 0; 상자 세션 0.05회).
   - 대전 성능, 실차 실행 조건, 학습 절차(플래그 190개, 실패할 때마다 체크포인트를 이어 붙인 실행)에 대해서는 맞지 않다.

### 1.4 출력: 행동이 정확히 무엇인가 [확인]

**출력 20개 = 10단계 × (조향, 속도).** — `plan_steps.py:100-173`

- 각 값은 tanh 후, 그 단계에서 **도달 가능한 구간**에 선형으로 펼쳐진다.
  - 조향: 직전 ±0.32 rad(서보 3.2 rad/s × 0.1 s), 조향 끝과 타이어 한계 안.
  - 속도: 직전 ±0.5 m/s(가속·감속 5 m/s² × 0.1 s), 타이어 횡가속 표의 **95 %**로 정한 곡률 한계 안.
- 시작점은 policy가 추정한 속도와 직전에 명령한 조향이다.
- 이것을 운동학 자전거 모델로 굴려 1초짜리 10점 계획을 만든다.

**RL이 다루는 행동은 출력 #0(첫 단계 조향)과 #10(첫 단계 속도) 두 개뿐이다.** — `plan_rl.py:2225-2227, 2263-2264, 2837-2839`

- 이 둘에만 pre-tanh Gaussian 잡음을 넣고 log-prob을 계산한다.
- 나머지 18개는 평균만 쓰고, "꼬리 손실"로 지도학습한다. 목표는 그 결정 뒤 0.2–1.0 s 동안 **차가 실제로 있던 자리와 속도**이고, 이 기록은 잡음이 섞인 rollout에서 온다 (`plan_rl.py:3627-3641, 3920-3961`, args `tail_target driven`, `tail_consistency 1.0`).
- 꼬리 손실은 trunk에도 흐른다. trunk로 가는 크기는 PPO gradient의 약 0.5배로 자동 조절된다(`tail_trunk_ratio 0.5`).

**결정 주기: 0.1 s.** 한 결정 = 제어 4스텝(25 ms 간격).

**출력이 조향·속도가 되는 경로**

- **학습·정기 시험**: 계획의 첫 0.1 s 명령 4개 → `GymEnv.ideal_cmd`.
  - 시뮬레이터가 학습 차의 상태를 **운동학 자전거 모델의 결과로 덮어쓴다** (`sim.py:1470-1501`).
  - 참 상태 기준의 모터·브레이크·서보 속도 한계만 지킨다.
  - 미끄러짐, 서보·모터 지연, 추종 오차가 없다. 접촉만 시뮬레이터가 처리한다.
- **콘솔·실차**: 10점 계획을 MAP(또는 MPC) 추종기가 동역학 차에서 따라간다. 이 조건으로 정기 시험을 하지는 않는다 (§3.12).

### 1.5 보상과 종료 (hs43b, update ≥ 150) [확인] — `plan_reward.py:41-45, 358-516`, `plan_rl.py:2524-2539, 2989-3007`

| 항 | 값 | hs43b에서 |

| 거리 shaping | γΦ(s′)−Φ(s). Φ = −(계획 점들의 벽 기준 최단거리 평균)/한 바퀴 길이 | update 100→150에 걸쳐 0으로 줄임 → **0** |

| 강한 접촉 = return 끝 | 충돌 속도 ≥ 1 m/s면 그 결정에서 return을 끊음(끝값 0). 차는 그 자리에서 계속 달리고 기억은 유지 | 켜짐(`hard_contact_ends`) |
| 계획 충돌 비용, 멈춤 비용, 역주행 비용 | 0 | 꺼짐 |
| 판 끝 | 시간 초과(40 s, 장면 판은 13 s)만. bootstrap은 V(s_t) | — |

**크기 비교 [추정·계산]**

- γ=0.995, 0.1 s 결정에서 가치 V ≈ Σγ^(73k) ≈ 2.5–3.3바퀴.
- 강한 접촉 한 번은 명시 비용 약 0.16–0.3바퀴에 더해 끊긴 가치 V(s′) ≈ 2.5–3.3바퀴를 잃는다. 약 20초 주행분이다.
- 끊긴 가치는 빠른 policy일수록 크다. 즉 같은 접촉이라도 빠를수록 벌이 커진다.

### 1.6 PPO 설정 [확인] — hs43b `args.json`, `plan_rl.py:2442-2445, 3340-3357, 3466-3472, 3784-4120`

| 항목 | 값 |
|---|---|
| 학습 차 수 | 1536 (GPU 1개, 원격 서버) |
| rollout 길이 | 64 × K 결정. K는 2–4에서 잡음 규모에 따라 자동 → 128–256결정(12.8–25.6 s) |
| update당 결정 | 19.7만–39.3만 |
| minibatch | 8K개(16–32). 하나 = 차 48–96대의 **전체 시퀀스** |
| epoch | 4 |
| actor 걸음 | minibatch gradient를 '합쳐서' 한 걸음. 합치는 수는 잡음 규모로 자동이고 줄지 않음(`accum_ratchet`): 8 → 22 → **32(=전부)**. 결과: **update당 actor Adam 4걸음** |
| critic 걸음 | minibatch마다(update당 최대 128) |
| lr | 3e-4 → 1e-4 선형(1500 update 기준, u950에서 약 1.7e-4). Adam eps 1e-5. 체크포인트에 optimizer 상태 없음 |
| γ / λ / clip | 0.995(0.1 s 기준, 약 20 s 지평) / 0.95 / 0.2 |
| 값 손실 | 0.5·MSE, vf_coef 0.5. 값 clipping 없음, return 정규화 없음 |
| advantage | minibatch마다 평균 0·표준편차 1로 정규화 |
| gradient clip | 0.5 (합친 gradient에 적용) |
| entropy 보너스 | 없음 |
| 탐색 표준편차 | 학습되는 log_std에 하한 적용: 첫 단계 조향 0.3, 속도 0.4(`torch.maximum`). 실제 파라미터는 0.299 / 0.399로 **하한 아래에 붙어 있음** → §2.6 |

## 3. 설계 심사 (리뷰어 관점)

### 3.1 경험량 — **타당 (병목 아님)**
- 3.1억 결정(약 8,700 차-시간)은 적지 않다 [확인].
- 문헌과 비교 [문헌]:
  - Swift(드론, Kaufmann et al., Nature 2023): PPO 약 1억 스텝을 작업용 PC에서 1시간 안쪽.
  - CaRL(Jaeger et al., 2025): PPO 수억 샘플.
  - GT Sophy(Wurman et al., Nature 2022): 콘솔 천여 대로 수일. 이것보다는 적다.
- 핵심은 양이 아니라 효율이다. **곡선이 5천만 결정 뒤 평평**하다 [확인]. 양을 늘려도 소용없다는 직접 증거다.

### 3.2 알고리즘 계열(on-policy PPO, score-function) — **의심**
- 이 문제의 특성:
  - 한 결정(0.1 s)의 행동이 return에 주는 영향이 작다(cm 단위 경로 차이).
  - return 분산은 뒤따르는 수십 번의 잡음, 상자, 상대가 지배한다.
- 이런 조건에서 score-function 추정기의 신호 대 잡음은 나쁘다. 로그가 이를 보인다 [확인]:
  - B_noise 15만–60만 ≈ rollout 하나.
  - 합친 수가 32(=전부)에 도달해 update당 4걸음.
  - 이전 개발자의 측정(RQ2)도 minibatch 하나에서 신호가 잡음의 약 1/4이라고 한다 [주장, `out/analysis/rq2_term_split_scan31b2_u600.txt`].
- [문헌] 연속 제어 레이싱의 대표 성공 사례는 ∂Q/∂a를 쓰는 off-policy 계열이 많다.
  - GT Sophy: QR-SAC, replay. Fuchs et al. RA-L 2021: SAC.
  - Swift의 PPO는 상태 입력(추정 상태 + 게이트), 조밀한 진행 보상, 매우 빠른 시뮬, 작은 MLP라는 유리한 조건이었다.
  - CaRL은 PPO를 쓰되 아주 큰 batch와 '경로 진행률' 하나로 된 단순 보상으로 확장성을 보였다.
- 저장소에 `learn/sac.py`가 있지만 이 계획 형식으로 비교한 적은 없다 [확인: plan_rl은 PPO 전용].
- 덧붙임 [추정]: 퍼텐셜 shaping을 다시 켜는 것만으로는 이 SNR이 크게 나아지지 않는다. critic이 정확하면(설명분산 0.98) 퍼텐셜 shaping은 advantage를 바꾸지 않기 때문이다. 문제는 보상의 희소성이 아니라 **행동 하나의 효과가 작다는 것**이다.

### 3.3 행동 매개변수화(궤적 점을 행동으로) — **의심**
- **장점:** 도달 가능 구간에 펼치는 방식은 모든 출력을 실행 가능한 계획으로 만든다. 좋은 착상이다.
- **단점 1: 탐색이 0.1 s 깊이다.**
  - RL은 첫 0.1 s만 탐색하고, 다음 결정이 잡음을 바로 되돌린다.
  - 주행선 폭의 탐색은 중앙 0.18 m다 [계측].
  - 추월(차 폭 0.31 m + 여유, 옆으로 0.5 m 이상을 1–2 s 유지)이나 다른 주행선 같은 **시간적으로 이어진 기동**은 거의 표본으로 나오지 않는다.
- **단점 2: tanh 포화.** 속도 결정의 45 %가 포화돼 탐색 0, gradient는 분산만 보탠다 [계측].
- **단점 3: '궤적'의 꼬리는 RL이 최적화하지 않은 예측이다.** 실차에서 MAP이 따라가는 대상이 이 예측이다.
- [문헌] RL이 궤적 공간에서 탐색하도록 하는 방법들이 있다.
  - 계획 공간의 저차원 모양에 잡음 넣기, 옵션(낮은 빈도의 상위 결정).
  - 기존 planner 위에 잔차 학습: RaceMOP, Trumpp et al., TUM, F1TENTH 다중 차량.
  - 궤적 조건 RL 제어기: TC-Driver, Ghignone et al., ForzaETH.
  - Dreamer 기반 LiDAR 레이싱의 zero-shot 실차 이전: Brunnbauer et al., ICRA 2022.

### 3.4 보상과 종료 — **의심(대전에서는 부당)**
- 단독: 바퀴 보너스 + 접촉 비용 + 강한 접촉 종료는 바퀴 시간 목적과 대체로 맞다.
- 문제는 **크기 불균형**이다.
  - 종료 비용 V(s′) ≈ 2.5–3.3바퀴 > 명시 접촉 비용 0.16바퀴의 15배 [추정·계산].
  - 종료 비용이 속도에 비례한다. 빠르게 달리는 법을 익힐수록 같은 접촉의 값이 커진다.
- 대전:
  - 목적은 바퀴 수뿐이고 순위·추월 보상이 없다.
  - 내 책임의 강한 차 접촉은 약 3바퀴의 손실이다.
  - 그러면 "느린 차 뒤를 따라가기"가 학습 목적상 거의 최적이다. 이전 개발자 메모에도 "끊긴 return 약 2.5바퀴 대 깨끗한 추월 약 0.5바퀴"라는 기록이 있다 [주장, `plan_rl.py:1601-1608` 도움말].
  - [문헌] GT Sophy는 진행 보상에 더해 추월 보상과 책임 구분 충돌 벌점을 따로 두고, 대전 장면(출발, 슬립스트림, 추월)을 따로 섞어 학습했다.

### 3.5 특권 critic — **타당**
- 비대칭 actor-critic이다. 상자·상대·남은 거리를 critic만 보는 것은 표준적이다.
- 작은 결함:
  - 남은 시간 입력 오류(2.3).
  - 잡음 상태를 모름(2.8).
  - actor 기억이 아는 "이번 세션에 지나간 상자"는 critic이 참값(12 m 안 상자)으로 가지므로 문제없다.

### 3.6 Teacher–student — **해당 없음(배제됨)**
- 사용자 방침으로 교사·보조 목표를 쓰지 않는다 [주장, 메모].
- 리뷰어 의견 [추정]: 특권 교사 → 학생 증류는 탐색·신호 문제를 푸는 가장 검증된 수단 가운데 하나다(다리 로봇, 자율주행 일반). 이를 배제하면 §3.2–3.3의 부담이 그대로 RL에 남는다.
- 그런데 현재 학습기 안에도 지도 보조 손실이 세 개 남아 있다: 속도 추정, 꼬리, 기억 value. 방침과도 일관되지 않다.

### 3.7 탐색 — **부당**
- std가 하한에 고정돼 학습되지 않는다(2.6). entropy 보너스도 없다.
- 흰 잡음 10 Hz, 0.1 s 깊이다(3.3).
- 상관 잡음을 켜고 끄는 조건을 critic의 특권 정보로 사람이 정했다(2.8).
- 결과: 주행선은 일찍 굳고, 추월은 발견되지 않는다 [계측 + 확인].

### 3.8 상대 차 학습 — **부당(대회 기준)**
- 대전 판 30 %, 그 전부가 **자기 policy의 고정 복사본**이다 [확인, rc42a args].
  - 복사본 4개를 보관하고 25 update마다 새로 넣는다.
  - 상대는 평균 행동으로 달리고, 속도 배율은 0.2 확률로 1.0, 아니면 0.5–0.95다.
- 리그, exploiter, 대회형 상대(다른 팀의 모듈형 스택: 다른 주행선, 막기, 급정지)가 없다. 상대 예측 head는 시도했다가 현재 계열에서는 꺼져 있다 [확인, rc42a `pred_opp False`].
- **시험 상대도 자기 복사본**이다 [확인, exam4 머리말]. 학습 분포 밖 상대에 대한 일반화를 재지 않는다.
- [문헌] GT Sophy는 내장 AI와 여러 policy를 섞은 상대 집합을 썼다. RaceMOP은 다수 상대와 처음 보는 트랙에서 평가했다.

### 3.9 커리큘럼 — **타당한 착상, 효과 미검증**
- 다음 장치들은 각각 근거 있는 착상이다:
  - 장면 재시작(우선순위 리플레이 류)
  - 자기 주행선 위 상자
  - 늦게 보이는 상자 우선
  - 상대 속도 배율
- 다만 서로 겹쳐 켜져 있고, 각각의 기여를 같은 출발점·여러 시드로 잰 기록이 없다 [확인: 실행이 한 시드, 이어 받기 사슬].
- 장면 기억 staleness(2.5②)도 있다.

### 3.10 평가 — **의심**
- 좋은 점: 고정 시드, 처음 보는 상자 배치, 128 세션 × 90 s, 신뢰구간 [확인].
- 문제:
  - ① 정기 시험은 **모두 '계획대로 정확히'**다. 도구에는 MAP 모드가 있는데 쓰지 않았다 [확인, `exam_record.py ... ideal`].
  - ② 대전 상대가 자기 복사본이다.
  - ③ 학습 시드가 하나다.
  - ④ 시험 결과로 체크포인트를 고른다. 같은 시험으로 고르고 보고하므로 낙관 편향이 있다.
  - ⑤ 같은 시험 안에서 외부 기준선(예: 모듈형 스택)과 비교하지 않는다.

### 3.11 시뮬–실차 — **부당**
- 학습 차는 운동학 모델로 덮어쓰기 때문에 동역학 무작위화가 의미 없다.
- 계획은 타이어 표의 95 %까지 쓴다 [확인].
- MAP 추종의 차이는 커밋 기록에 "이상 실행 7.0–7.15 s 대 MAP 7.48–7.70 s"로 남아 있다 [주장, 커밋 a4b56c4]. 연구 로그에는 "MAP으로는 벽 접촉이 크게 늘었다(조정 전 9/세션)"는 기록이 있다 [주장].
- [문헌] Swift는 실측으로 맞춘 잔차 동역학·지각 모델로 이 차이를 줄였다. TC-Driver는 타이어 모델 불일치에 강한 추종 RL을 목표로 했다.

### 3.12 실험 절차 — **부당**
- plan_rl.py는 11-07에 만들어졌고, 3주 동안 이 파일을 바꾼 커밋이 112개, CLI 플래그가 190개다 [확인].

- 모든 변형이 같은 판(7.4–7.6바퀴/분)에 선다 [확인]. 바뀐 플래그가 아니라 **공통 기반(행동 설계, 탐색, 알고리즘, 목적)**이 병목이라는 강한 정황이다.

## 5. 살릴 것 / 버릴 것

### 살릴 것
- GPU 병렬 시뮬레이터와 실측 기반 센서 모델(LiDAR 잡음·누락·기울기), graph capture. 1536대에서 rollout 4.2k 결정/s다.

- 시험 체계(고정 시드, 처음 보는 배치, 세션 단위 신뢰구간). 단, map 모드와 비자기 상대를 추가해야 한다.
- 비대칭 critic(특권 정보), GAE·PPO의 기본 구현. 큰 줄기는 정확하다.
- 도달 가능 구간에 펼치는 계획 매개변수화. 실행 가능성 보장은 유지하되 포화 문제는 손봐야 한다.
- 잡음 규모 측정(McCandlish 식)과 보상 항별 gradient 분해 도구. 진단 도구로 가치가 높다.
- 장면 재시작 착상. 기억 staleness를 고치고 효과를 재야 한다.

### 버릴 것 (또는 동결하고 git 기록으로만 남길 것)
- 플래그 190개짜리 단일 학습기. 확정된 설계 하나로 최소 학습기를 새로 쓴다.
  - 정리 대상: `branches 2`, `pace-caps`, `line-shifts`, `plan-roll`, `roll-grow`, `commit-plan`, `plan-grad-cost`, `intent`, `pred-clear-oracle`, `hold-*` 등. 기본값이 꺼진 가지들이다.
- 실패 장면마다 플래그를 하나씩 붙여 체크포인트를 이어 받는 방식. Adam 없이, 한 시드로, 여러 플래그를 동시에 바꾼다.
- `max(log_std, floor)` 방식의 하한. 하한 + softplus 매개변수화나 entropy 목표로 바꾼다. 로그에는 실제로 쓰는 std를 찍는다.
- 자기 복사본만 쓰는 대전 학습·시험.
- '계획대로 정확히'만 쓰는 정기 시험.
- 잡음 경로를 목표로 하는 꼬리 학습. 평균 policy 경로를 쓰거나, 꼬리를 RL이 책임지는 설계로 바꾼다.

## 6. 가장 중요한 권고 3가지

1. **더 학습하기 전에 기준선과 평가부터 고정한다.**
   - 현재 최고 단독·대전 체크포인트를 (i) 계획대로 정확히, (ii) MAP + 동역학, (iii) 자기 복사본이 아닌 상대(예: 기존 모듈형·FTG 상대, 여러 속도)로 시험한다.
   - 처음부터 학습하는 실행은 시드 2–3개로 반복한다.
   - 이후 모든 변경은 이 묶음에서 기준선을 이겨야 채택한다. (H4·H6 반증과 3.10·3.12 해결.)
2. **탐색을 '궤적 단위'로 다시 설계하고, 학습 전에 계측으로 확인한다.**
   - RL 행동을 첫 0.1 s가 아니라 1 s 계획의 저차원 모양(옆 오프셋·속도 배율 같은 몇 개 계수)에 둔다.
   - 그 위에 시간 상관 잡음을 넣고, 결정 빈도를 낮춘다(예: 상위 2–5 Hz).
   - std 매개변수화를 고치고, tanh 포화를 피한다(구간 중심 기준 매개변수화나 Beta 분포).
   - 성공 기준: 학습 전 계측에서 1–2 s 창의 옆 경로 폭 p90 ≥ 0.5 m, 강제 추월 장면에서 의미 있는 성공률. (H1)
3. **학습 신호와 대전 목적을 바로잡는다.**
   - (a) 같은 예산으로 off-policy actor-critic(특권 critic, replay)과 현재 PPO를 단독 과제에서 정면 비교한다. 저장소에 `sac.py`가 있다.
   - (b) 대전은 접촉 = return 종료 대신 제약 기반 가격(라그랑주 승수, 목표 접촉률)으로 바꾸고, 자기 복사본 외 상대를 섞는다.
   - (c) 추월을 직접 보상하지 않더라도, 기대값 계산(⑤)으로 목적이 추월을 허용하는지 먼저 확인한다. (H2·H3)
