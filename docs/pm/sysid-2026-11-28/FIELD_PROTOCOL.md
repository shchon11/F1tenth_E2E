# 새 장소 도착 후 20분 주행 시험 절차 (2026-11-28)

> **최신 안내서는 `docs/bag_recording_guide.md`이다.** 이 1쪽 절차서는 요약이고, 아래 숫자는 2026-11-28 도구 수정 뒤의 코드(`f1sim/f1sim/bag_profile/thresholds.py`)에 맞춰 고쳤다. 어긋나면 안내서와 요약 끝의 문턱값 표를 따른다.

목적: 새 장소에서 차·장소 프로필을 정하는 데 필요한 값을 20분 안에 녹화한다. 레이스 bag으로는 정해지지 않는 값(최대 마찰, 조향 이득과 언더스티어의 분리, 순수 지연과 서보 지연의 분리, 저항)을 겨냥한다. 근거는 `REPORT.md` 4~6장이다.

## 0. 공통 규칙

- **bag 하나에 시험 하나.** 폴더 이름 끝에 시험 이름을 붙인다. 예: `20261201-101500_T3-launch-brake`.
- **구간 표시 토픽.** 시험을 시작할 때와 끝날 때 `/sysid/segment`(std_msgs/String)에 시험 이름을 한 번씩 낸다. 예: `ros2 topic pub --once /sysid/segment std_msgs/String "data: T3 start"`. bag_profile은 이 토픽이 있으면 시험별 계산을 그 구간 안으로 자르고, 없으면 아래 '자동 인식 규칙'으로 찾는다. 요약의 "계산에 쓴 구간" 표에 값마다 어느 쪽이 쓰였는지 적힌다. 같은 표시는 3번씩 내도 된다(2 s 안의 되풀이는 한 번으로 셈).
- **녹화할 토픽.** `/ackermann_cmd`, `/commands/servo/position`, `/sensors/servo_position_command`, `/commands/motor/speed`, `/sensors/core`, `/sensors/imu/raw`, `/odom`, `/scan`, `/tf_static`, 위치 추정 결과(`/pf/pose/odom`), `/map`.
- **매 bag 앞뒤에 정지 5~10 s.** IMU 바이어스와 자이로 단위를 확인하는 데 쓴다.
- **차 설정 기록 `setup.yaml`.** 서보 변환식, VESC 서보 창, ERPM 이득, 전류·회생 한계, IMU 단위, LiDAR tf, 타이어 종류를 적는다. bag 폴더 안이나 옆에 두거나 `--setup`으로 지정하면 bag_profile이 bag에서 역추정한 값과 항목별로 대조한다. 손으로 잰 값(바퀴 각 표, 질량, 무게중심, 요 관성, LiDAR 실측)은 `hand_measured:` 칸에 적는다. 양식은 안내서 2.3.

## 1. 시험 순서

|---|---|---|---|---|---|
| T0 | 정지 10 s | 0.5분 | — | IMU 바이어스, 자이로 단위(deg/s 여부), LiDAR 정지 잡음 | 바퀴 속도 < 0.02 m/s인 상태가 1 s 이상(바이어스, 명령 토픽 유무와 무관). 자이로 크기 < 0.03 rad/s는 LiDAR 정지 잡음 블록에서만 쓰고 그때 바퀴 속도는 < 0.01 m/s (구현됨) |

## 2. 돌리기

```bash
python -m f1sim.bag_profile <bag 폴더> --car comp_car_map08x23 --out <출력 폴더> [--setup setup.yaml]
```

- 각 시험 bag에 따로 돌린다. `--car`는 비교 기준이 되는 차 프로필이다(현재 차 설정은 8월 대회 때와 같아 `comp_car_map08x23`. `pre_map12x16`은 사전 차). 설정 지문(서보 변환식, ERPM 이득, 자이로 단위, 회생 전류, LiDAR 장착, 지연)이 다르면 요약에 '아니오'로 표시된다.
- 출력:
  - `car_calibration.yaml`, `place_profile.yaml`: 값, 오차, 출처, 상태
  - `summary.md`: 그림, 계산에 쓴 구간, 대체된 값, setup.yaml 대조, '못 잰 것' 두 목록, 문턱값 표
- '못 잰 것 (a)'(이런 녹화로 잴 수 있었는데 조건이 모자란 것, 모자란 만큼이 숫자로 나옴)가 빌 때까지 해당 시험을 다시 녹화한다. 비면 "이 bag으로 잴 수 있는 것은 다 쟀음"이 찍힌다. '(b)'(바퀴 각 실측, 질량, 무게중심, 요 관성, LiDAR 실측)는 주행으로 안 나오는 값이라 `setup.yaml`의 `hand_measured:`에 적는다.
- 장소 프로필로 넘길 최소 값은 다음과 같다(REPORT.md 5장).
  - 같은 차: **트림 b**
  - 차 설정이 바뀐 경우: 트림 b + **지연 τd**
  - 마찰: T6이 있을 때만 상한까지 나온다. 없으면 '하한만'으로 남는다.

## 3. 현장에서 바로 확인할 것

- 자이로 단위(rad/s 또는 deg/s)와 가속도 단위(g)가 setup.yaml과 같은가. 7월 bag 7개가 deg/s였다.
- 서보 창 양 끝이 둘 다 '측정됨'인가. 대회 차는 오른쪽이 −0.254 rad에서 잘렸다(왼쪽은 +0.412 rad). 그래서 오른쪽 조향 0.3 rad는 잘린 값이 된다.
- 회생 전류 최소가 의도한 설정인가. 대회 차 −30 A, 사전 차 −5 A였다.
- bag_map 축척 검사가 1.00 ± 0.03 안에 드는가.
