## 읽는 법

- 제품마다 **가져올 패턴 / 가져오지 않을 것 / 우리 화면 어디에 쓰는가**를 적었다.
- 확인 수준을 항목마다 표시했다.
  - **[문서]** 이번 작업에서 공식 문서·공식 안내 페이지·위키를 찾아 글로 확인한 것.
  - **[안내글]** 제3자 안내글·포럼 글로만 확인한 것(틀릴 수 있음).
  - **[기억]** 찾아보지 못했고 내가 아는 범위에서 쓴 것. 구현 전에 실제 화면을 한 번 봐야 한다.
- **실제 게임 화면 그림은 한 장도 직접 보지 못했다.** 검색 도구가 글만 돌려주었기 때문이다. 아래 서술은 글로 확인한 구조와 기억을 합친 것이다. 화면 배치의 세부(여백, 정확한 탭 이름과 순서)는 그대로 믿지 말 것.
- 가져오는 것은 **구조와 행동 방식**이다. 로고, 고유 그림, 서체, 이름, 색 조합은 가져오지 않는다.

## 1. Gran Turismo 7

**가져올 패턴**

1. **설정 시트 여러 장.** 차 한 대에 설정 시트를 여러 개 만들어 이름 붙여 두고 바꿔 끼운다. 안내글들은 "기본 시트를 건드리지 말고 새 시트에서 고쳐라, 날씨·대회 규정별로 시트를 따로 둬라"고 권한다. **[안내글]** → 우리 차고의 '빌드'가 이것이다. 실차 2호, 대회 기본 차, Orin Nano로 바꿔 본 차를 시트처럼 나란히 둔다.
2. **값을 바꾼 뒤 종합 수치를 다시 계산.** 차 설정에서 값을 바꾸고 버튼을 눌러야 성능 점수(PP)가 다시 계산된다. 점수는 AI가 차를 몰아 여러 시험을 돌린 결과라고 한다. **[문서: 공식 온라인 설명서 'Performance Points and BoP']**, 계산 방식은 **[안내글]** → 우리는 차고에서 값을 바꾸면 '이 차로 기준 드라이버가 달렸을 때 랩 예상'을 요청해서 받는 식으로 쓴다. 자동이 아니라 요청형이어야 하는 이유도 같다(계산이 무겁다).
3. **금·은·동 기준 기록.** 면허 시험은 통과 기준(동)과 더 어려운 두 기준(은·금)을 두고, 시범 주행을 볼 수 있다. **[안내글·위키]** → 훈련소 성적표의 종목별 표식. 단, 우리는 메달이 아니라 '기준 드라이버보다 좋아짐 / 차이 없음 / 나빠짐' 세 가지로 바꾼다(아래 '가져오지 않을 것').
4. **차가 주인공인 차고.** 어두운 무대에 차 한 대, 주변에 얇은 글자. **[기억]** → 허브의 조합 영역과 차고 3D.
5. **안내형 과제 목록(카페의 메뉴북).** 다음에 할 일을 몇 개의 작은 과제로 묶어 주고 끝내면 다음 것을 준다. **[기억, 미확인]** → 허브 '다음 할 일'. 우리 것은 이야기가 아니라 '값이 비어 있는 곳'에서 자동으로 생긴다.

**가져오지 않을 것**

- 세계 지도 모양의 메뉴. 예쁘지만 목적지 7개를 찾는 데 시간이 든다. 연구자는 하루에 수십 번 화면을 오간다.
- 밝고 여백이 큰 화면 전체 분위기. 표와 곡선이 많은 훈련소·분석을 감당하지 못한다(02 문서의 A안 참고).
- 금·은·동이라는 절대 등급. 우리 성적은 '기준 드라이버 대비'여야 하고 오차 범위가 붙어야 한다. 메달은 오차를 숨긴다.
- 크레딧·수집·보상 연출. 연구 도구에 가짜 보상을 넣지 않는다.

**적용**: 차고(빌드 시트, 비교), 훈련소(성적표), 허브(조합 무대, 다음 할 일).

## 2. Forza Motorsport (2023) / Forza Horizon

**가져올 패턴**

1. **묶음별 튜닝 탭.** 타이어, 기어, 얼라인먼트, 스태빌라이저, 스프링, 댐핑, 공력, 브레이크, 디퍼렌셜처럼 부위별 탭으로 나뉜다(안내글은 탭이 11개라고 한다). **[안내글]** → 차고의 탭: 한눈에 / 섀시·질량 / 타이어 / 구동계 / 조향 / 센서 / 컴퓨터 / 외관.
2. **슬라이더 한 줄에 '지금 값'과 '원래 값'을 같이.** **[기억]** → 차고 시트의 '기준과 차이' 열. 우리는 여기에 '오차'와 '출처' 열을 더한다.
3. **고른 항목에 대한 짧은 설명이 항상 한자리에.** 무엇을 올리면 차가 어떻게 달라지는지 한두 문장. **[기억]** → 차고에서 행을 고르면 펼쳐지는 '왜 중요한가 / 실측하려면'.
4. **부품을 달아야 조절 항목이 열림.** 안내글: 스태빌라이저 조절은 레이스용 부품을 달아야 가능. **[안내글]** → 센서를 달아야 그 센서의 값이 열린다(카메라 빈 자리).

**가져오지 않을 것**

- 업그레이드 상점과 등급 문자(A·S 등). 우리 부품은 실제로 가진 것만 있다.
- 영어 약어가 가득한 표기. 한국어 낱말로 푼다.

**적용**: 차고 전체.

## 3. Assetto Corsa Competizione

**가져올 패턴**

1. **셋업 화면의 탭 묶음.** 타이어, 전자 장비, 연료·전략, 기계적 그립, 댐퍼, 공력으로 나뉜다. **[안내글: 여러 셋업 안내에서 탭 이름 일치]**
2. **기본 프리셋에서 출발.** '안전' 프리셋과 '공격' 프리셋이 차마다 있고 거기서 고친다. **[안내글: 'Safe preset' 언급]** → 훈련소 레시피, 차고의 '대회 기본 차'.
3. **주행 중 Esc로 바로 셋업에 들어가 고치고 다시 나감.** **[안내글]** → 레이스 주행 중 일시정지 → 차고의 해당 탭으로 건너갔다가 같은 세션으로 돌아오기.
4. **피트 전략처럼 '미리 정해 둔 일정'.** 급유·타이어 교체 계획. **[기억]** → 장애물이 '놓였다가 치워지는' 일정을 세션 막대 위에 그린다(레이스 HUD 왼쪽 위).

**가져오지 않을 것**

- 클릭 수십 번이 필요한 작은 +/− 버튼만의 조절. 키보드 화살표와 직접 입력을 같이 준다.
- 실차 팀 수준의 항목 수. 우리 차는 조절할 수 있는 물리 값이 훨씬 적다. 대신 값마다 '얼마나 믿을 수 있나'가 더 중요하다.

**적용**: 차고, 레이스 구성, 레이스 HUD의 일정 막대.

## 4. iRacing

**가져올 패턴**

1. **세션 종류를 먼저 고르고 나머지를 채우는 구성 순서.** 시험 주행 / 타임 어택 / 레이스 등 종류가 먼저, 차·트랙·조건이 다음. **[기억]** → 레이스 구성: 형식(예선 형식 / 본선 형식 / 자유 주행 / 직접 몰기) → 조합 확인 → 상대·장애물 → 출발.
2. **차고의 요약 탭.** 셋업 화면이 요약 탭으로 열리고 불러오기·저장·초기화가 있다. **[안내글, 판촉 사이트라 신뢰 낮음]** → 차고 '한눈에' 탭.
3. **공유 셋업.** 다른 사람이 올린 셋업을 받아 쓴다. 공식 패치 노트에 '공유 셋업 버튼' 언급. **[문서: 공식 패치 노트]** → 팀 2~5명이 빌드·장소 프로필·레시피를 공유.
4. **인터페이스를 통째로 다시 지은 최근 개편.** 공식 글이 "완전한 재설계와 재구축"이라고 설명. **[문서]** → 참고: 그들도 옛 화면과 새 화면을 한동안 같이 운영했다. 우리도 옛 콘솔을 한동안 남겨야 할 수 있다(05 문서의 이행 메모).

**가져오지 않을 것**

- 웹 화면과 시뮬 화면의 이중 구조. 우리는 처음부터 웹 하나다.
- 등급·면허·일정표 같은 서비스 요소.

**적용**: 레이스 구성 로비, 차고 요약, 공유.

## 5. F1 24 (EA)

**가져올 패턴**

1. **화면 요소를 하나씩 끄고, 크기와 투명도를 조절.** 공식 접근성 안내: 화면 표시 요소를 개별로 끄기·크기·불투명도 조절, 트랙 지도는 미니맵/전체 지도 중 선택, 미니맵 회전 끄기. **[문서: EA 접근성 안내]** → 레이스 HUD의 표시 토글(궤적·LiDAR·자취·그립·근거)과 판 단위 켜고 끄기.
2. **구간 기록의 색 문법.** 보라 = 전체 최고, 초록 = 자기 최고, 노랑 = 개선 없음. 게임 문서에서는 확인하지 못했고 포럼 글에서 사용자들이 그렇게 부른다. **[안내글]** 모터스포츠 중계의 오랜 관례이기도 하다. **[기억]** → 우리 기록 숫자 전체에 같은 문법.
3. **랩 타이밍 판: 현재 랩, 최고 대비 차이, 구간 막대.** **[기억]** → HUD 위 가운데.
4. **순위 탑과 사건 알림.** 화면 옆의 세로 순위표, 위쪽의 짧은 알림 띠. **[기억]** → 바퀴 기록 표, '세션 최고' 띠.
5. **결과 화면: 순위·최고 랩·벌점 한 장.** **[기억]** → 대회 채점 방식 결과지.

**가져오지 않을 것**

- 실제 대회 브랜드를 닮은 방송 그래픽 모양. 색 문법만 가져온다.
- 화려한 전환 연출. 연구자는 같은 세션을 하루에 수십 번 돌린다.

**적용**: 레이스 HUD, 결과 화면, 훈련소·허브의 기록 숫자.

## 6. Trackmania (2020)

**가져올 패턴**

1. **편집 방식 전환: 블록 / 아이템 / 묶음(매크로블록).** 기능키로 바꾼다(F2 블록, F3 아이템). **[문서: 커뮤니티 위키, Maniaplanet 문서]** → 트랙 스튜디오: 벽 그리기(덕트 호스 선) / 물건 놓기(상자·기둥) / 묶음(헤어핀·시케인 조각).
2. **검증 깃발.** 깃발이 빨간색이면 저장해도 정식 트랙이 아니다. 눌러 보면 무엇이 모자란지 나온다. 직접 완주해야 초록이 된다. **[문서: Maniaplanet 문서 — 깃발 세 가지 상태, 요건 표시]** → 우리 검증: 닫힌 코스인가, 폭 최소값, 기준 드라이버 완주. 통과해야 '장소에 올리기'가 열린다.
3. **만든 사람이 세운 기준 기록.** 검증 주행 기록이 그 트랙의 기준이 된다. **[기억]** → 코스마다 '기준 드라이버 랩'이 자동으로 붙는다.
4. **단순 편집기와 고급 편집기.** **[문서: Maniaplanet 문서에 고급 모드 언급, 2020판의 차이는 미확인]** → 자동 생성(슬라이더 몇 개) / 직접 그리기.

**가져오지 않을 것**

- 격자에 딱딱 맞는 블록만으로 짓기. 덕트 호스는 자유 곡선이다.
- 높이·점프·루프. 우리는 평면이다.

**적용**: 트랙 스튜디오.

## 7. BeamNG.drive

**가져올 패턴**

1. **부품 선택이 트리.** "부품 선택기는 트리처럼 되어 있고, 어떤 부품은 다른 부품에 달려 있다. 앞에서 무엇을 골랐느냐에 따라 못 고르는 부품이 생긴다." **[문서: 공식 문서 'Creating new vehicle configs']** → 차고 왼쪽 '달린 센서' 트리. 자리(슬롯)와 부품을 구분한다.
2. **튜닝 항목은 고른 부품에 따라 달라짐.** "튜닝 메뉴는 고른 부품에 따라 다른 설정을 준다." **[문서]** → 센서 기종을 바꾸면 시트 항목이 바뀐다.
3. **구성을 이름 붙여 저장, 공식 구성은 덮어쓰지 말 것.** **[문서 + 포럼]** → '대회 기본 차' 같은 기준 빌드는 잠금.
4. **부품에 마우스를 올리면 3D에서 그 부품이 빛남.** **[기억]** → 차고에서 고른 부품이 라임색.

**가져오지 않을 것**

- 수백 줄짜리 깊은 트리를 그대로 노출. 우리 트리는 2단까지만.
- 개발자용 앱 창이 떠다니는 화면. 판은 정해진 자리에.

**적용**: 차고(트리, 3D 강조), 05 문서의 '부품 트리' 컴포넌트.

## 8. MoTeC i2

**가져올 패턴**

1. **랩 겹쳐 보기와 시간 차 누적 곡선.** 공식 소개: 여러 랩 겹치기, '시간 차 곡선'으로 랩 사이 어디서 시간을 얻고 잃었는지 보기, 두 랩의 위치를 지도에서 같이 움직이기. **[문서: MoTeC i2 소개]** → 분석의 랩 비교. 시뮬 대 실차 bag 비교도 같은 틀.
2. **가로축을 거리로 / 시간으로.** 랩 타임이 다른 두 랩은 거리 축으로 겹쳐야 같은 코너가 맞는다. 작업 화면마다 고른다. **[문서: MoTeC 포럼의 직원 답변]** → 분석 기본은 거리 축, 훈련소 곡선은 진행률/걸린 시간.
3. **작업 화면 묶음(워크북·워크시트).** 목적별로 차트 배치를 저장. **[문서]** → 분석의 '보기' 프리셋: 코너 진입 / 제동 / 접촉 직전 3초.
4. **지도 위에 값 색칠.** 얻고 잃은 시간을 지도 선에 색으로. **[안내글: 포럼에서 사용자가 만드는 법 토론]** → 미니맵 선을 속도·시간 차로 칠하기.

**가져오지 않을 것**

- 검은 바탕에 원색 선이 수십 개 겹친 기본 모습. 계열은 여섯 개까지, 순서가 정해진 색.
- 작은 글씨와 빽빽한 메뉴. 

**적용**: 분석(랩 비교, 시뮬 대 실차), 훈련소 곡선, 레이스 HUD의 '최고 랩 대비'.

## 9. Foxglove

**가져올 패턴**

1. **상태 구간 띠.** 이산 값이 바뀌는 구간을 가로 띠로 보여 주고, 지금 재생 시각을 세로 선으로 표시한다. **[문서: 공식 문서 'State Transitions' 패널]** → 분석의 사건 띠(접촉, 장애물 놓임/치움, 추월 중), bag 마법사의 '어느 구간을 어떤 추정에 썼나'.
2. **실시간이면 최근 30초, 녹화면 전체 구간.** 데이터 종류에 따라 기본 범위가 다르다. **[문서: 변경 기록]** → 주행 중 차트는 최근 12초, 다시 보기는 전체.
3. **재생 막대 하나에 모든 패널이 동기.** **[기억]** → 분석과 다시 보기.
4. **패널 배치를 저장하고 공유.** **[기억]** → 분석의 보기 프리셋.
5. **토픽 목록에서 고르면 맞는 패널이 열림.** **[기억]** → bag 마법사 1단계 '토픽 인식'.

**가져오지 않을 것**

- 무엇이든 놓을 수 있는 빈 판. 우리는 목적이 정해진 화면에 정해진 판을 둔다. 자유 배치는 분석 화면에서만, 그것도 프리셋 위주로.
- 토픽 이름(`/scan`, `/odom`)을 그대로 보여 주는 것. '거리 센서 스캔', '바퀴 속도'로 바꿔 보이고 원래 이름은 작은 글씨로.

**적용**: 분석, bag 마법사.

## 10. Unreal Editor

**가져올 패턴**

1. **뷰포트 + 개요 트리 + 세부 패널의 3분할.** **[기억]** → 차고(트리 · 3D · 시트), 트랙 스튜디오(물건 목록 · 코스 · 속성).
2. **뷰포트 안의 조작 손잡이와 보기 방식 전환.** 이동·회전 손잡이, 원근/위/옆 보기. **[기억]** → 센서 장착 위치를 3D에서 끌기, '앞 비스듬히 / 위 / 옆 / 자유'.
3. **세부 패널의 값 옆 '기본값으로 되돌리기' 화살표.** **[기억]** → 시트 행의 '기준 값으로'(키 D).

**가져오지 않을 것**

- 도구 막대와 메뉴의 양. 게임을 만드는 도구이지 게임이 아니다.
- 창을 떼어 내고 붙이는 자유 배치.

**적용**: 차고 3D, 트랙 스튜디오.

## 레퍼런스에 없어서 우리가 만든 것

레퍼런스 어디에도 없고, 이 제품의 정체성이 되는 것 세 가지.

1. **출처 배지와 오차.** 게임의 차 값은 전부 참이다. 우리 값은 실측 / 추정 / 규격 / 가정으로 나뉘고 오차가 붙는다. 모든 숫자 옆에 이것이 붙는다(02 문서 8절).
2. **드라이버 호환.** 게임에서 사람은 어떤 차든 몬다. 학습된 드라이버는 훈련한 센서 구성에서만 달린다. 차고의 자물쇠 표시와 '달릴 수 있는 드라이버' 목록이 이것을 다룬다.
3. **판단 시간 예산.** 드라이버가 한 번 판단하는 데 걸리는 시간이 차에 달린 컴퓨터의 예산 안에 드는지. 차고와 HUD에 같은 막대로 나온다.
