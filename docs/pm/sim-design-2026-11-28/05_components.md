# 05. 컴포넌트 목록과 상태

2026-11-28 · 시뮬레이터 재설계 디자인 방향 기준서 5/5 · 토큰: `tokens.css` · 견본: `mockups/base.css`와 각 목업의 `<style>`

## 0. 쓰는 법

- 색·글자·간격·시간은 **`tokens.css`의 의미 토큰(`--c-*`, `--t-*`, `--s-*`, `--dur-*`)만** 쓴다. 원색(`--p-*`)과 숫자 값을 컴포넌트에 직접 쓰지 않는다.
- 아래 표의 '견본' 열은 목업에서 그 컴포넌트가 그려진 곳의 CSS 선택자다. 목업 CSS는 정지 화면용이라 상태(호버 등)가 없다. 상태는 이 문서가 기준이다.
- 컴포넌트 이름은 제안이다. 프레임워크는 정하지 않았다.

### 모든 컴포넌트에 공통인 상태 규칙

| 상태 | 규칙 |
|---|---|
| 기본 | 선 `--c-line` 또는 `--c-line-strong`, 글자 `--c-text` / `--c-text-2` |
| 호버 | 바탕 `--c-bg-hover`, 선 한 단 밝게. `--dur-1`. 포인터가 없는 조작(키)에는 호버가 없다 |
| 포커스(키보드) | 바깥 2px `--c-focus` 선, 1px 띄움. **호버와 다르게 보여야 한다.** 모든 조작 가능한 것에 필수 |
| 누름 | 바탕 한 단 어둡게, 주 행동은 `--c-accent-press`. `--dur-2` |
| 선택 / 켜짐 | 왼쪽 3px `--c-accent` 띠 + 바탕 `--c-accent-tint`(행·항목) 또는 선과 글자가 `--c-accent`(버튼·칩) |
| 비활성 | 글자 `--c-text-disabled`, 선 `--c-line`, 포인터 기본. **왜 안 되는지 한 줄을 옆에 쓴다**(툴팁에만 두지 않는다) |
| 오류 | 선 `--c-danger`, 바탕 `--c-danger-tint`, 아래에 사실 한 문장 + 다음 행동. 빨간 테두리만 두지 않는다 |
| 불러오는 중 | 자리 그대로 두고 값 자리에 가는 가로줄이 흐름. 0.4초 안에 오면 아무것도 보이지 않게. 판 전체를 가리는 돌림 표시 금지 |
| 비어 있음 | 무엇이 비었는지 + 채우는 방법 한 문장 + 버튼 하나 |

| **DiagDrawer** 진단 서랍 | 개발자용 문구·로그 | 아래에서 올라오는 판 | 닫힘 / 열림 | (목업 없음) |
| **Picker** 고르기 창 | 차·장소·드라이버·코스 고르기 | 찾기 칸 + 목록(이름, 한 줄 요약, 핵심 수치, 호환 표식) + 미리 보기 | 항목: 기본 / 호버 / 선택 / 못 고름(호환 안 됨: ✕ + 이유) | (목업 없음) |

## 2. 조작

| 컴포넌트 | 하는 일 | 상태 | 견본 |
|---|---|---|---|
| **Button** | 보통 행동 | 기본(선 `--c-line-strong`) / 호버 / 누름 / 선택(`.sel`: 라임 선·글자) / 비활성 / 위험(`.danger`: 멈추기·지우기) / 진행 중(글자 옆 점 깜빡임, 다시 못 누름) | `.btn` |
| **PrimaryAction** 주 행동 | 화면에 **하나** | 기본(라임 채움, 깎은 모서리, 키 딱지) / 호버(`--c-accent-hover`) / 누름 / 비활성(회색 채움 + 아래에 "왜 못 하는지") / 진행 중("시작하는 중 — 지도 읽기") | `.btn.go` |
| **GhostButton** | 덜 중요한 행동 | 글자만. 호버에 바탕 | `.btn.ghost` |
| **Segmented** 둘셋 중 하나 | 보기 전환, 가로축 전환 | 칸: 기본 / 호버 / 선택(HUD·뷰포트 위: 라임 채움. 판 안: 흰 채움) / 비활성 | `.seg-ctl`, `.seg2` |
| **SubTabs** | 화면 안 탭 | 선택: 위 3px 라임 띠(차고) 또는 아래 사선 띠(훈련소). 탭에 작은 지표(가정 비율 막대, 개수) 가능 | `#tabs a`, `#head .sub a` |
| **Slider** | 연속 값 | 홈 + 손잡이(아래가 뾰족한 라임 딱지). 기본 / 호버(손잡이 밝게) / 끄는 중(값 풍선) / 비활성 / 범위 밖(손잡이 빨강 + 이유). **범위 띠**를 같이 그린다: 가정 = 호박 점선 띠, 추정 = 실선 띠 | `.sl` |
| **StepDial** 단계 고르기 | 4단계쯤의 거친 설정(상자 수, 길이) | 칸 ×4 + 낱말. 채운 칸 `--c-text-2` | `.steps` |
| **NumberField** | 직접 입력 | 바탕 `--c-bg-well`, 숫자 오른쪽 정렬 + 단위. 기본 / 포커스(라임 선) / 고침(값 왼쪽에 작은 점) / 오류(범위 밖: 허용 범위를 적음) | `#promote .nm div` |
| **ToggleChip** 표시 토글 | HUD 표시 켜고 끄기 | 키 딱지 + 낱말 + 색 견본. 꺼짐(흐린 글자) / 켜짐(글자 밝게 + 개체 색 네모) | `#layers .tg` |
| **KeyCap** | 키 표시 | 선 + 아래 2px. 안내용이라 상태 없음 | `.key` |

## 4. 목록과 탐색

| 컴포넌트 | 하는 일 | 상태 | 견본 |

| **LidarScope** | 스캔을 위에서 | 270° 부채, 거리 고리, 점(벽 청록 / 상자 흰색), 가장 가까운 점까지 선, 뒤 90° 호박 빗금 | `#scope` |
| **ElevationDiagram** 단면 도해 | 옆에서 본 스캔 높이 | 세로 확대 배율을 제목에 적음. 지금 값 = 라임 실선, 가정 범위 = 호박 점선 쐐기, 기준 물체, 문제 구간 빗금 + 문장 | `#elev` |

공통: 격자선 `--c-chart-grid`, 축 글자 `--t-data-s` `--c-text-4`, 바탕 `--c-bg-well` 또는 판 그대로. 범례는 차트 밖 칩으로(누르면 켜고 끔). 가리키면 세로 선 + 값 표.

## 8. 구현 메모

1. **글꼴.** 목업의 `mockups/fonts/*.woff2`는 한글 2,350자로 줄인 미리 보기용이다. 제품에는 원본 전체를 넣는다(IBM Plex Sans KR · IBM Plex Mono · Saira Condensed · Saira Semi Condensed, 모두 OFL 1.1). 줄인 파일을 다시 배포할 때는 OFL의 예약 이름 조항을 확인할 것.
2. **Saira 숫자.** 폭이 서로 다르고 `tnum`이 없다(글꼴 파일에서 확인). 바뀌는 숫자는 `DigitReadout`으로, 표 숫자는 Plex Mono로.
3. **사선과 깎은 모서리**는 `clip-path`로 그렸다. 포커스 선이 잘리므로 포커스는 바깥 감싼 요소에 그린다.
4. **HUD 판의 배경 흐림**은 WebGL 캔버스 위에서 비싸다. 원격·저사양에서는 끄고 바탕 불투명도를 0.92로.
5. **상태 견본 화면.** 이 문서의 상태를 컴포넌트마다 한 줄로 늘어놓은 견본 화면을 구현 첫 주에 만든다. 목업 4장에는 상태가 없다.
6. **목업 파일 구조.**

| 파일 | 내용 |
|---|---|
| `tokens.css` | 토큰. 제품에 그대로 가져가는 유일한 파일 |
| `mockups/base.css` | 위·아래 띠, 판, 버튼, 배지, 태그, 표의 견본 스타일 |
| `mockups/chrome.js` | 위·아래 띠를 그리는 스크립트 |
| `mockups/scene.js` | 정지 장면 그리개(코스, 차, LiDAR 광선, 원근 투영). **견본용. 제품 코드로 쓰지 않는다** |
| `mockups/0N_*.html` | 화면 4장. 브라우저에서 바로 열림(1920×1200 고정) |
| `mockups/0N_*.png` | 최종 렌더 |
| `mockups/_v0`, `_v1` | 고치기 전 렌더(04 문서) |

7. **옛 콘솔에서 가져올 것.** 현황 보고서에 따르면 지금 콘솔의 차 모델(glb), 주행 자취·궤적·LiDAR 겹쳐 보기, 장애물 편집의 조작(놓기·끌기·돌리기), 시작 단계 진행 문구는 쓸 만하다. 새 화면의 `Viewport3D`, 트랙 스튜디오의 '물건 놓기'가 그 조작을 이어받는다.
